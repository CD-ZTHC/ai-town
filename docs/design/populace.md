# 群众 —— 设计方案

> 状态：已实现（2026-10-04，分支 `feat/populace`）。§14 列出这次没做的部分。
> 决策（2026-10-04 确认，见 §12）：
> 1. 没配置的世界按「主地图公开地点数 × 6，8~120 人」推出默认群众。
> 2. 做「与路人交谈」（P0，占用旅人聊天的次数）。
> 3. **任何分级的群众人数都可以减少**（伤亡、搬走）；分级只决定情绪的上限和文案的口吻。
> 4. 民意调用的开关与频率放进设置页。
> 5. night-watch 的 `population` 改写成多类人群，作为验收样例（§13）。
> 相关：[night-watch.md](night-watch.md) §4.10 群众与死亡（本方案取代其中「群众只记数字」的部分）；[adventure.md](adventure.md) §3.5 区域休眠；[map-evolution.md](map-evolution.md) §6.1 地图压力表；[multi-world.md](multi-world.md) §7.2 调度级别。

## 0. 一句话概括

给内核加一个**所有世界都有**的「群众」层：具名居民以外的普通人（小镇的街坊、城市的市民、村里的村民、过路的游客）按作息在地图上来往；节日、天气、新建筑、传闻、怪事会让他们聚集或散开；一个低频的「民意」调用决定集体的倾向；群众的动向反过来写进居民的记忆、变成建设的点子、改变威胁的伤亡。

**不给每个群众接模型。** 群众的看点是集体趋势——萤火节傍晚码头挤满了人、地铁站出事后一夜清空——而不是几百条独白。模拟靠规则，模型只出方向。

## 1. 改动之前

| 能力 | 位置 | 当时的情况 |
|---|---|---|
| 地点人口 | `spec.population`（只有 night-watch 配了）→ `dark.population[loc] = {alive, dead}` | 挂在黑暗叙事状态下，只会因伤亡减少 |
| 群众伤亡 | `casualties()`（`server/sim/dark.ts`）、`crowdStrike()`（`server/story/threats.ts`） | 找不到有人口的地点时照样记 n 人 |
| 路人小人 | `crowdFigures()` / `drawPasserby()`（原在 `public/js/render/dark.js`） | 纯前端，每个地点最多 4 个，只在有 `population` 的世界画 |
| 群体心智的模板 | `swarmMind()`（`server/story/creatures.ts`） | 每两小时最多一次、P2、队列忙时让路，模型只给去向 |
| 节日、天气、建筑状态、士气 | `spec.calendar`、`town.weather`、`setBuildingState`、`town.crisis` | 只影响具名居民和提示词 |
| 传闻 | 导演节拍 `spreadNews` | 只写进具名居民的记忆和信念 |
| 威胁的线索 / 误导 | `ThreatType.clues / decoys` | 只有具名居民会相信 |

结果：云溪、小红帽、破晓远征的地图上除了具名居民空无一人；「出事后大家都搬走了」无从表现；群众不影响任何人。

## 2. 原则

1. **通用，按分级调节情绪上限。** 内核和前端里不出现任何世界专有的名词。同一套机制，在轻松向世界里表现为赶集、过节、围观，在黑暗世界里表现为逃难、伤亡。
2. **规则执行，模型定方向。** 人流、人数、情绪都由规则计算；模型（§6）只产出意图，经内核校验、限幅后再交给规则。没配置模型、预算用完或关掉民意时，世界照样热闹。
3. **可复现。** 规则层**不用随机数**，同样的输入永远得到同样的人流；需要「随机」的地方（出发时刻错开、路人的称呼、放哪条线索）都用字符串哈希。
4. **人数守恒。** 群众只会在去处之间流动、在「外地」进出、或者死去；不会凭空出现或消失（「转正」成居民时扣一个人，§8.6）。
5. **比例尺自适应。** 小村子里一个小人就是一个人，大城市里一个小人代表一批人。
6. **便宜。** 每个游戏小时结算一次，复杂度与「地点数 × 人群类别数」成正比，与人数无关。前端不逐人下发坐标。
7. **不配置也能用。** 没写 `populace` 的世界按地图推出默认群众（§3.3）；旧的 `population` 自动转换（§10）。

## 3. 数据模型

### 3.1 规格：`spec.populace`

```jsonc
"populace": {
  // 人群类别（最多 8 类）；写成空数组表示这个世界没有群众（例如开天之前的混沌）
  "groups": [
    {
      "id": "commuter", "name": "上班族", "emoji": "💼",
      "size": 3000,                                  // 总人数（含在外地的）
      "homes": ["river_view", "river_flat"],         // 住处（建筑或地点 id）：只决定出门、回家从哪里走
      "work": ["hospital", "store", "archive"],      // 上工的地点（可选；不写时按地点种类挑）
      "haunts": ["metro", "store", "night_street"],  // 常去的地点（不写时所有公开地点都去）
      "rhythm": "day",                               // day 早出晚归 / night 夜猫子 / always 全天 / visitor 只在节日、白天来访
      "traits": { "timid": 0.5, "curious": 0.3, "social": 0.4 }, // 胆小、好奇、爱凑热闹（0~1）
      "look": { "tones": ["#4a5568", "#5b6270"] }    // 衣服的颜色（可选）
    }
  ],
  "outside": { "name": "外地", "via": ["metro"] }, // 进出世界的出入口；不写时用主地图的渡口
  "scale": 0,                                       // 一个小人代表几个人；0 = 自动（§7.1）
  "capacity": { "plaza": 300 }                      // 地点容量（可选）
}
```

- 校验：`validatePopulace`（`server/kernel/populace-spec.ts`），接在 `validateSpec` 里。地点 id 必须存在、人数 0~100000、类别 ≤ 8、性情 0~1、颜色 `#rrggbb`。
- 天气规格新增可选字段 `outdoor`（-1~1，对户外活动的影响）；不写时按天气 id 推断：`storm / snow / sand` 为 -0.9，`rain / drizzle / fog` 为 -0.6，`sunny / clear` 为 0.3。
- 容量不写时按面积分：全体群众人数的 4 倍按各公开地点的面积摊开，每处至少 6 人。

### 3.2 运行状态：存档字段 `populace`

定义在 `server/sim/populace-rules.ts`（`PopulaceState`），登记在 `server/sim/state.ts` 的状态表里，旧存档缺的字段用初值补齐。

| 字段 | 含义 |
|---|---|
| `at` | 去处 → 类别 → 人数。去处是地点 id，或两个虚拟去处 `@home`（在家，看不见）、`@out`（在外地，不在世界里）。路上的人不在这里 |
| `flows` | 正在路上的人流：`{ id, group, from, to, n, start, eta, cause }`，`cause` 是 `routine / gather / flee / leave / return / arrive / depart` |
| `dead` | 地点 → 累计伤亡 |
| `mood` | 类别 → `{ fear, joy, anger }`（0~1） |
| `fearHours` | 类别 → 恐惧持续高于出城阈值的小时数 |
| `beliefs` | 群众相信的传闻（最多 12 条）：`about / claim / confidence / source / loc / tone`；来自威胁线索的还带 `truth`、`threat`（不进任何提示词和视图） |
| `intents` | 民意给的、还在生效的去向偏好 |
| `gatherings` | 进行中的聚集：`{ loc, kind, from, until, text }` |
| `casualties` | 最近两天的伤亡记录（排斥用） |
| `summary` | 最近一次民意的摘要 |
| `topics` | 传闻话题 → 出现过的游戏日（找「长期被议论的话题」用） |
| `peaks` / `norm` | 最近 4 天各地点的人数高峰；地点「平常的高峰」（指数平均） |
| `mind` | 民意调用的计数：当天第几次、上次时刻、大事签名、是否有待加的一次、上次提诉求的日子 |
| `seen` / `noticed` / `heard` / `clued` | 居民注意到人数变化、听到群众传闻、威胁往群众里放线索的去重记录 |

### 3.3 默认群众（没写 `populace` 的世界）

`resolvePopulace(spec)` 按规格推出实际配置，结果按规格对象缓存，规格变了自动重算：

- 写了 `populace`：用它；`groups` 为空（或人数都是 0）时没有群众。
- 只有旧的 `population`：转成一类「市民」，人数为总和，非公开地点当住处，公开地点当常去处。
- 都没有：一类人群，名字用 `voice.resident`（默认「居民」），人数 = 主地图公开地点数 × 6（8~120 人），常去处 = 主地图的公开地点，住处 = 主地图上像住宅的建筑（`house / cottage / apartment / cabin / inn …`）。分级 `cozy` 的世界再加一类「游客」（`visitor` 作息，人数为三成）。

创世流程没有改动：新生成的世界走默认推算；想要更细的人群可以在世界包里写 `populace`。

## 4. 规则层：每个游戏小时结算一次

纯函数在 `server/sim/populace-rules.ts`：`step(state, config, input)`。`input` 是 `Town` 整理好的显式快照（`server/sim/populace.ts` 的 `popPlaces / popStimuli / popWeather / popTravel`）。`Town.advance` 在 `darkHourly()` 之后调用 `populaceTick()`：每次推进都让到点的人流落地，跨过整点时结算一次。

### 4.1 每个去处的权重

对每一类人、每个去处：

```
基线    = 作息里这个钟点「上工 / 吃饭 / 闲逛」的比重 ÷ 同用途的地点数
修正 m  = pull × (0.4 + 0.6 × max(好奇, 爱凑热闹)) − push × (0.5 + 胆小)
        + 天气（户外 × 0.8；下雨时室内 +0.3 × 雨势）
        + 民意偏好 × 1.5
权重    = 基线 × e^clamp(m, −5, 3)
在家    = 作息里「在家」的比重 × e^clamp(恐惧 × 2 × (0.5 + 胆小) + 雨势 × 0.4, 0, 3)
```

- 节日、聚集这类 `pull ≥ 1` 的大事，不常去那里的人也会去凑热闹（给一个小的基线）。
- `closed` 的地点权重为 0，`damaged` × 0.4，`ruin` 只有好奇的人会去（× 0.15 × 好奇）。
- 地点的用途按种类和 id 归类：`work`（工坊、农场、学校、医院、商店、车站……）、`food`（咖啡馆、茶馆、酒馆、集市、街……）、`fun`（广场、公园、码头、花园、神社……），可以同时属于多类，都不像时算 `fun`。写明了 `work` 的人群，别的「上工」类地点对他们只是常去的地方（例如车站）。

吸引（pull）与排斥（push）的来源：

| 来源 | 类型 | 强度 | 适用世界 |
|---|---|---|---|
| 节日 | 吸引 | 进行中的日历事件，地点 +2.5；当天开始之前 +0.5 | 全部 |
| 聚集 | 吸引 | 进行中的聚集 +2.2 | 全部 |
| 新落成的地方 | 吸引 | `addBuilding / addOutdoorPlace` 之后 3 天，+1.2 逐日衰减 | 全部 |
| 具名居民在的地方 | 吸引 | 每位醒着的居民 +0.12，最多 +0.6 | 全部 |
| 点名地点的传闻 | 吸引 / 排斥 | `tone` 为 good / bad，0.8 × 可信度 | 全部 |
| 进行中的事件 | 排斥 | 征兆 0.8 / 爆发 1.6 / 扩散 2.6，18 格内按距离衰减 | 有威胁的世界 |
| 在外作祟的威胁 | 排斥 | 最近的地点 1.0，8 格内衰减（野怪不算） | 有威胁的世界 |
| 最近的伤亡 | 排斥 | `min(2.5, log2(1 + n))`，两天内衰减 | 有伤亡的世界 |
| 夜里捣乱的异界生物 | 排斥 | 生物群今晚的去处 +0.6 | 有异界生物的世界 |
| 灯与结界 | 减半 | 地点 5 格内有带 `light` / `ward` 标签的构筑物，排斥减半 | 全部 |

### 4.2 人流

1. 去处 = 家 + 醒着的区域里的公开地点。按权重把在城里的人（含正在赶去那里的人）整数分配（最大余数法）。
2. 超过容量的部分回家；容量按这类人在全体中的比例分摊。
3. 多出来的人按惯性挪一部分：`惯性 = 0.35 + 0.35 × 恐惧`（最多 0.7，越害怕走得越快），至少挪 1 人；只有真在那里的人能走。
4. 起点与终点配对成人流，同一对起点终点、同一类人每小时一条。出发时刻在整点后 0~40 分钟内按哈希错开，到达时刻按两点的曼哈顿距离 ÷ 2.5 格/分钟（4~60 分钟）。
5. 人流到点才计入目的地；目的地这时关门了就回家。
6. `cause`：目的地吸引 ≥ 1.5 记为 `gather`，起点排斥 ≥ 1 记为 `flee`，其余为 `routine`。

### 4.3 出城与进城

- 恐惧持续高于「分级上限 × 0.65」满 24 小时：每小时有城里人数的 1% 搬走（先从家里走），记为 `leave`。
- 恐惧低于「上限 × 0.4」且士气 ≥ 45：每小时有外地人数的 3% 回来，记为 `return`。
- `visitor` 作息：节日当天 09:00~23:00 有九成在城里，平日 10:00~18:00 有两成五，其余时间在外地；按差额的一半进城（`arrive`）或离开（`depart`）。

### 4.4 情绪

每类人每小时更新一次：

- **恐惧**：`src` = 各地点排斥 × 熟悉程度（常去、上工的地方 1，别处 0.5）的最大值；目标 = `上限 × (1 − e^(−src × (0.6 + 0.8 × 胆小) / 2))` + 士气低落项 `max(0, (45 − 士气) / 60)`。危险叠加会饱和：一个游荡的威胁约 0.4，扩散中的事件约 0.7，几处一起才接近上限。上升快（× 0.35）、回落慢（× 0.12）。
- **欢乐**：目标 = 0.3 + 全城喜事 × 0.7 ± 0.15（天气）− 恐惧 × 0.3。喜事来自节日（0.8，当天开始之前 0.4）、庆祝 / 赶集的聚集（0.5）、新落成的地方（0.3）。
- **不满**：目标 = 常去的地方关门的数量 × 0.08（最多 0.4）+ 物资低于 40 的部分 + 害怕太久没人管（0.3）+ 请愿的聚集（0.3）；变化慢（× 0.1）。

分级决定恐惧的上限和口吻，**不决定人数能不能减少**——任何分级里群众都可能搬走或伤亡（决策 3）：

| 分级 | 恐惧上限 | 群众的典型样子 |
|---|---|---|
| `cozy` | 0.5（表现为「不安」） | 赶集、过节、围观、抱怨；真遇上怪事也会搬走 |
| `adventure` / `epic` | 0.75 | 避开出事的地方、议论 |
| `dark` / `tragic` | 1.0 | 搬走、恐慌、伤亡 |

### 4.5 伤亡

`casualties()` 在有群众的世界里改为调用 `harmCrowd(loc, n)`：从那个地点**此刻**的人里按类别比例扣，`dead[loc]` 累加，返回实际扣掉的人数。给的是坐标时，落在 12 格内最近、此刻有人的地点；附近没人就没有伤亡——躲开的人是安全的。士气、附近居民的记忆、日志照旧；记忆的措辞按分级：致死分级是「又死了 k 个人」，其余是「又有 k 个人出了事，被送走了」。没有群众的世界（开天）保留原来的逻辑。

## 5. 群众的信念

- **来源：**
  - 导演的 `spreadNews`：写给具名居民的同时，群众也听说（话题、说法、可信度、点名的地点）。
  - 民意调用（§6）的 `rumors`。
  - 威胁的线索：进行中的事件处在爆发或扩散阶段时，每天 09:00 后往群众里放一条说法，从 `clues`（真）和 `decoys`（误导）里按哈希挑，日志记「某某一带开始流传一种说法：……」。
- **作用：**
  - 点名地点、带 `tone` 的传闻进入 §4.1 的吸引 / 排斥。
  - **真线索会救命**：群众相信了某个威胁的一条真线索（可信度 ≥ 0.5）时，这个威胁的 `crowdStrike` 伤亡减半；信了误导就白忙一场。
- **流回具名居民：** 居民在有 3 人以上群众的地点时，每小时有四分之一的机会（按哈希）听到一条自己还不怎么信的说法，可信度打八折，来源 `crowd`，记一条「在某处听街上的人说：……」；每人每天最多一条。
- 传闻每小时可信度 × 0.99，低于 0.15 时忘掉；同一个话题以新的为准、可信度取高的。

## 6. 心智层：民意调用

### 6.1 什么时候调

- 每游戏日 07:00 之后的第一个整点调一次。
- 有大事时加一次（距上一次至少 2 小时），当天总数不超过 `POPULACE_MIND_PER_DAY`。「大事」是下面这些组成的签名变了：进行中事件的阶段、正在进行的节日、最近一次建筑类世界操作（新建、改状态、拆除）、单日伤亡是否超过总人口的 2%。
- 条件与 `swarmMind` 一致：`llm.enabled() && llm.budgetLeft() > 0 && !llm.isBusy()`，否则跳过。
- 标签「群众心智」，P2，`tier: 'fast'`，最多 1500 token，失败不重试。
- 设置（「世界」分组，保存后立即生效）：`POPULACE_MIND`（开关，默认开）、`POPULACE_MIND_PER_DAY`（1~6，默认 2）。

### 6.2 输入

系统提示词沿用世界的（设定、分级、时代、支柱），加一句「这一次你是普通人的集体心声，不点名伤害任何具体的人」。用户提示词：时间与天气、各类人群（在城里 / 在外地的人数、人最多的 4 个地点、三项情绪）、上一次的摘要、最近 10 条大事（事件、伤亡、传闻、世界变化、人来人往、场景、民意、征兆、死亡）、群众在传的说法、可以去的地点。

### 6.3 输出（`SCHEMAS.populace`）

```jsonc
{
  "summary": "≤40字，今天大家在想什么",
  "prefer": [{ "group": "类别id 或 all", "loc": "地点id", "weight": -1~1, "hours": 1~24, "reason": "≤20字" }], // 最多 4 条
  "rumors": [{ "about": "≤12字", "claim": "≤40字", "confidence": 0~1, "loc": "地点id 或 null", "tone": "good/bad/null" }], // 最多 2 条
  "gathering": { "loc": "地点id", "kind": "market/celebrate/watch/mourn/pray/protest/flee", "from": "HH:MM", "hours": 1~6, "text": "≤30字" } | null,
  "demand": { "text": "≤40字，希望添点什么、修好什么、关掉什么" } | null
}
```

### 6.4 校验与执行

- 地点不存在的偏好、传闻地点、聚集丢弃；类别不存在的偏好当作对所有人；`weight`、`hours`、`confidence` 限幅；偏好最多同时留 12 条。
- 摘要、传闻、聚集说明、诉求都经过 `guard` 的关键词检查（按世界分级），不通过的丢弃。
- 聚集：同一地点已有进行中的聚集时不再加；最多同时 4 个；日志「👥 HH:MM 起，大家要去某处赶集：……」。
- 诉求：交给世界架构师的意图队列 `architect.enqueue(text, 'populace')`，由架构师按平常的流程写成建设提案（考据、终审、议事照旧）。来源显示为「群众的呼声」；架构师每天最多收 1 条，群众每 3 个游戏日最多提 1 条。
- 摘要写进日志（类型 `populace`，进动态流的「剧情」分组），也进入导演、日报、规划的提示词。

## 7. 前端

### 7.1 比例尺

| 总人数（`scale` 为 0 时） | 一个小人代表 | 每个地点最多画 |
|---|---|---|
| ≤ 150 | 1 人 | 12 |
| ≤ 1500 | 10 人 | 10 |
| 更多 | 对数换算：`round(log10(n + 1) × 2.2)` | 8 |

室内地点的人在屋里看不见，门口最多站 3 个。

### 7.2 下发的数据

- **快照**（每秒几次）：`crowd` = 地点 → 各类人数（只有醒着的区域、有人的地点）。
- **`populace` 推送**（每次结算、民意之后；也随初始数据下发）：比例尺、总人数、类别（名字、emoji、颜色）、进行中的聚集、民意摘要、正在路上的人流。人流带服务器算好的道路折线 `[x0, y0, x1, y1, …]`（`findPath`，隔一个点取一个），按人数从多到少，每次推送最多新算 40 条，算过的缓存到人流落地。

### 7.3 画法（`public/js/render/populace.js`）

- **地点里：** 户外在站位附近踱步，位置由地点、序号决定（每帧稳定）；各类人按人数比例分配小人，衣服是类别的颜色。
- **人流：** 按 `start / eta` 在折线上插值，几个人一串；`flee / leave` 步子更快。
- **聚集：** 户外聚集的地点，小人围成一圈。
- **外观：** 简化的像素小人，比居民小一号、略透明，避免抢戏。
- **点击：** 路人的点击 id 是 `p:地点:类别序号:序号`，悬停显示类别与地点，点击弹出搭话的窗口（§9）；游戏模式里点路人也一样。
- **故事面板：** 新增「👥 群众」页：民意摘要、在这里 / 在外地 / 伤亡、各类人群（人数、在家、在路上、人最多的地方、三项情绪条）、聚集、非日常的人流、街上在传的说法、各处人数。

## 8. 反馈回路

### 8.1 具名居民

- 每小时比较各地点的人数：翻倍（且增加不少于 `minN`）或减半（原来不少于 `minN`）时，在场醒着的居民记一条「某处一下子热闹起来，来了好多人」/「某处的人一下子少了很多，冷冷清清的」，重要度 3~5；每个地点每天最多一次。`minN = max(3, 城里人数 ÷ 地点数 ÷ 3)`。
- 规划一天的提示词加一行「镇上的情形」：民意摘要、昨天人最多和最冷清的地方、今天的聚集。
- 群众的传闻按 §5 流回居民。

### 8.2 导演与日报

- 导演提示词的「居民」后面加一行群众：民意摘要、人最多的 3 个地方、搬走或在外地的人数、聚集、街上在传的说法。`populace` 日志算作导演看的重要动态。
- 日报的素材里加「街头巷尾」一行，提示可以写进 `gossip`。

### 8.3 规则表达式

| 函数 | 含义 |
|---|---|
| `crowd('地点id')` | 此刻在这个地点的群众人数 |
| `crowdMood('fear/joy/anger')` | 全体群众某种情绪的加权平均 |
| `crowdBelieves('话题')` | 群众对某个话题的确信度 |
| `crowdGone()` | 搬走、还没回来的人数（不含来访的人） |
| `deserted('地点id')` | 人数不到「平常高峰」的一成（至少 2 人以下）；世界没有群众时为假 |
| `crowdDead()` | 改为群众的累计伤亡（加上旧存档里的人口伤亡） |

`alone(e)` 语义不变（只看具名居民）。世界包可以用这些函数写规则，例如「广场空了以后，夜里的规则更容易触发」。

### 8.4 建设

民意的诉求进架构师的意图队列（§6.4），和居民聊天里冒出的点子、地图压力表的意图走同一条路。

### 8.5 地图压力

`pressure.ts` 新增两项：

- **拥挤**：最近 3 天里有 2 天人数高峰达到容量的九成 → 「某处这几天总是挤满了人，扩建它，或者在附近再添一处同类的地方」（排在破败之后、闲置之前）。
- **冷清**：连续 3 天没有群众去的公开地点 → 写进给架构师的地图现状。
- 最近有群众去过的建筑不再算「闲置」。

### 8.6 新居民

同一个传闻话题在最近 4 天里有 3 天出现过时，人员流动的提示词里加一段：「普通人这几天一直在议论某事；新人可以是本地群众里的一员，因为这件事站了出来」，并允许 `arrive` 带 `"fromCrowd": "类别id"`。新人登场时那类群众少一个人。

## 9. 路人

### 9.1 临时身份（`GET /api/passerby?loc=&g=&i=`）

按「地点、类别、序号、游戏日」的哈希确定：称呼 = 形容词（高个子的、上了年纪的、提着篮子的……）+ 类别名，例如「上了年纪的老街坊」；一句话按情绪（害怕 / 不满 / 高兴 / 平常）、所在地点的聚集、群众在传的说法从模板里挑。同一天点同一个小人得到同一个人。不调模型。地点只能是公开地点或 `@home / @out`（路上的人），序号 0~999。

### 9.2 和路人说话（`POST /api/passerby/chat`）

标签「与路人交谈」，P0。上下文：临时身份、所在地点、民意摘要、心情、群众在传的说法、弹窗里最近 6 句。回复 ≤ 60 字。和旅人聊天共用 `chat` 额度、同样的审核（决策 2）。不写进任何具名居民的记忆；对话只留在弹窗里；动态流记一条「旅人和某处的某人搭话」。

## 10. 兼容与迁移

- **规格：** 旧的 `population` 在 `resolvePopulace` 里转成一类「市民」（§3.3），字段保留；新世界包写 `populace`。没有群众的世界（`groups` 为空）里，`threats.init` 仍按旧逻辑读 `population`。
- **存档：** 第一次初始化群众时，旧存档 `dark.population` 里的死者数照抄进 `populace.dead`，第一类人群按死者总数扣人，其余的人从家里重新开始；之后 `dark.population` 清空。
- **规格变化：** 新增的类别放进来（常住的在家、来访的在外地），删掉的类别连同它的人流一起清走。
- **视图：** 威胁视图不再带 `crowd`；黑暗叙事面板的「各处人口」只剩没有群众的旧世界会显示，伤亡总数改为加上群众的伤亡。
- **区域休眠：** 休眠区域里的地点不参与结算——里面的人原地不动，也没有人去；醒来后接着结算。不做补算。

## 12. 决策记录

| # | 问题 | 结论（2026-10-04） |
|---|---|---|
| 1 | 默认规模 | 主地图公开地点数 × 6，8~120 人 |
| 2 | 与路人交谈 | 做；P0，和旅人聊天共用额度与审核 |
| 3 | 低分级的群众伤亡 | 任何分级的人数都可以减少；分级只决定情绪上限与口吻 |
| 4 | 民意调用的频率 | 放进设置：`POPULACE_MIND`、`POPULACE_MIND_PER_DAY` |
| 5 | night-watch | 改写成多类人群，作为验收样例 |

实施中另外定下的：

- **诉求不直接写世界操作**，交给架构师的意图队列：模型凭一句话写不出合法的 `addBuilding` 参数，架构师本来就做这件事。
- **末班车的触发条件不改。** 设计稿里想加 `deserted('metro')`，但「或」会让结伴进站也出事（推翻「结伴进站的人都平安回来了」这条真线索），「且」又会让开局有人的时候末班车几乎不出手。群众对威胁的影响改由「躲开就没有伤亡」和「真线索让伤亡减半」体现。
- **开天之前没有群众**：《开天》的世界包写 `"populace": { "groups": [] }`。
- **出城阈值是「上限 × 0.65」**，速度每小时 1%：恐惧曲线是饱和的，0.8 几乎到不了；2% 时夜巡三天就走掉七成上班族，太快。

## 13. 验收样例：night-watch

`population`（共 7000 人）改写成 `populace`，总人数不变：

| 类别 | 人数 | 住处 | 上工 | 常去 | 作息 | 性情 |
|---|---|---|---|---|---|---|
| 💼 上班族 | 3000 | 江景公寓、滨江小区 | 医院、便利店、档案馆 | 地铁站、便利店、夜市街、茶馆、广场、公园 | `day` | 胆小 0.5、爱凑热闹 0.4 |
| 🎒 学生 | 1500 | 滨江小区、槐荫巷七号楼 | 临川七中 | 公园、便利店、夜市街、广场 | `day` | 好奇 0.7 |
| 🧓 老街坊 | 1500 | 槐荫巷七号楼 | — | 茶馆、土地庙、槐荫巷、广场、公园、医院 | `day` | 胆小 0.6、爱凑热闹 0.8 |
| 🌃 夜归人 | 1000 | 江景公寓 | 医院、便利店、夜市街 | 夜市街、地铁站、便利店、公园 | `night` | 胆小 0.3 |

出入口是江桥地铁站。

无头运行 6 天（种子 3，不连模型）：第 3 天槐荫巷、江景公寓的事件进入扩散，胆小的老街坊恐惧先过 0.65；满一天后开始搬走，到第 7 天清晨老街坊走了 804 人、上班族走了 1554 人，学生和夜归人恐惧较低、留了下来；群众里流传着真假混杂的说法（「巷子里有灯的地方没出过事」「出事的人都用过医院的座机」）。

## 14. 这次没做的

| 内容 | 原因 / 以后怎么做 |
|---|---|
| 访客发布的事件按语气吸引或排斥群众 | 审核结果里没有「语气」；以后可以在事件审核时多要一个字段 |
| 具名居民的对话话题进入群众的信念 | 对话结果没有结构化的话题；可以复用信念传播的 `shareBeliefs` |
| 休眠区域醒来时补算 | 规则层是纯函数，可以快进；目前群众几乎都在主地图，先冻结 |
| 创世时让模型按设定写群众的类别 | 默认推算已经能用；以后在创世的世界包阶段加一步 |
| 每个世界单独的民意开关 | 目前只有全站设置；可以照人员流动的 `worldSettings.migration` 加 |
| 聚集的特殊画法（灯笼、朝向场景中心） | 现在只是围成一圈 |
