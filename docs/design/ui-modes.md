# 云溪镇 UI 2.0：观察 / 沉浸 / 游戏 三种模式 —— 设计方案

> 状态：草案，待评审。本文只做设计，不包含代码改动。
> 范围：`public/`（index.html、style.css、js/ui.js、js/main.js、js/render.js），以及游戏模式需要的少量服务端接口。

---

## 0. 一句话概括

把现在「所有面板同时铺满屏幕」的单一界面，拆成**三种按用途切换的模式**：

| 模式 | 给谁用 | 一句话 |
| --- | --- | --- |
| 🔭 **观察模式**（默认，现有界面的整理版） | 想看细节、做管理的人 | 信息完整、面板按需展开的「导演台」 |
| 🎬 **沉浸模式** | 想安静看小镇生活的人、挂机/屏保 | 隐藏所有界面，自动运镜 + 字幕，像看一部慢电影 |
| 🎮 **游戏模式** | 想亲自参与的访客 | 以旅人化身第三人称游玩：走路、靠近居民对话、接心愿、收集图鉴 |

模式之间共享同一个画布、同一条数据流，只切换 **HUD 布局、相机策略、输入映射** 三件事。

## 1. 现状盘点

### 1.1 当前界面构成

| 区域 | 位置 | 内容 |
| --- | --- | --- |
| 顶栏 `#topbar` | 顶部通栏 | 品牌、时钟、节日标签、🎭 故事、🌗 区域、访客/调速、8 个按钮（天气/事件/日报/关系/现身/建设/声音/帮助） |
| 名册 `#roster` | 左上 | 8 位居民卡片 |
| 检查器 `#inspector` | 右侧 400px | 居民详情 5 个标签页 |
| 动态流 `#feed` | 左下 380×320 | 5 个过滤标签 |
| AI 大脑 `#brain` | 右下 | 模型、用量、进行中的调用 |
| 小地图 | 右下角 | 导航 |
| 弹窗 `#modal` | 居中 | 日报、关系网、事件、故事、建设、帮助、化身 |

### 1.2 主要问题

1. **信息过载、画面被遮挡**：顶栏 + 名册 + 动态流 + AI 大脑 + 小地图 + 检查器同时存在时，1440×900 屏幕上可见的小镇面积不到 45%。像素小镇本身是最好看的部分，却被挤在中间。
2. **顶栏过长**：8 个按钮 + 4 个标签 + 调速器，`flex-wrap` 在 1280px 以下会折成两行，把名册和检查器的 `top: 92px` 撑乱。
3. **没有层级**：「AI 大脑」这种开发者信息和「居民在聊什么」这种核心内容视觉权重相同。
4. **访客参与感弱**：化身只能在弹窗里点地点名字瞬移式走路，无法直接在地图上操作；跟居民聊天仍需打开检查器切到「交谈」标签，和「我站在 TA 面前」的体验脱节。
5. **看不到故事高潮**：重要对话、剧情节拍发生时，只在动态流里多一行，镜头不会过去，很容易错过。
6. **移动端**：≤900px 时直接隐藏 AI 大脑和小地图，名册缩成头像，检查器占 60vh，动态流 200px——两者叠加后几乎看不到地图。
7. **样式散落**：`style.css` 409 行，颜色、圆角、阴影多处硬编码，后续加模式时难以统一换肤。

## 2. 目标与非目标

### 2.1 目标

- G1 默认界面下，小镇可见面积 ≥ 70%（1440×900，未选中居民时）。
- G2 一键（快捷键 / 按钮）在三种模式间切换，切换过程有 300ms 内的过渡动画，不重载页面、不断开 SSE。
- G3 沉浸模式可以**无人操作连续播放**：自动运镜到有意思的地方，对白以字幕呈现。
- G4 游戏模式让访客**只用地图操作**就能完成「现身 → 走到某人身边 → 聊天 → 看到对方记住自己」的闭环。
- G5 移动端三种模式都可用，游戏模式支持虚拟摇杆/点地移动。
- G6 不引入 npm 依赖、不引入构建步骤（保持原生 ES Modules + Canvas）。

### 2.2 非目标

- 不重做像素美术和渲染管线（`render.js` 只加相机与叠加层能力）。
- 不改变权限模型：访客/管理员能做的事与现在一致，游戏模式只是换一种入口。
- 不做账号系统；游戏进度只存在访客本机（`localStorage`）+ 服务端已有的化身/记忆。

## 3. 整体结构

### 3.1 模式状态机

```
             ┌─────────── Esc / 移动鼠标 3 次 ───────────┐
             ▼                                             │
   ┌──────────────────┐   I / 🎬   ┌──────────────────┐   │
   │  🔭 观察 observe  │ ─────────▶ │  🎬 沉浸 immerse  │ ──┘
   │   （默认）        │ ◀───────── │                  │
   └──────────────────┘   Esc      └──────────────────┘
        │      ▲
   G/🎮 │      │ Esc（二次确认是否保持化身）
        ▼      │
   ┌──────────────────┐
   │  🎮 游戏 play     │  ← 进入时若无化身，先走「现身」流程
   └──────────────────┘
```

- 状态保存在 `app.mode`，同时写到 `<body data-mode="observe|immerse|play">`，**CSS 负责大部分显隐**，JS 只负责相机策略和输入映射。
- 记住上次模式：`localStorage['town-mode']`；URL 参数 `?mode=immerse` 可直接进入（方便做成屏保/直播源/嵌入个人网站）。
- 公网只读模式（`perms.interaction=false`）下，游戏模式入口隐藏。

### 3.2 HUD 分层

将所有界面元素归入 4 个层级，每个模式声明每一层的可见性：

| 层 | 元素 | 观察 | 沉浸 | 游戏 |
| --- | --- | --- | --- | --- |
| L0 世界 | 画布、世界内气泡、名字 | ✅ | ✅（气泡改字幕） | ✅ |
| L1 状态 | 时钟、天气、节日/故事标签 | ✅ 顶栏 | 淡入淡出的角标 | ✅ 精简角标 |
| L2 导航 | 名册、小地图、模式切换 Dock | ✅ | ❌ | 小地图 + 附近的人 |
| L3 信息 | 动态流、检查器、AI 大脑 | 按需展开 | ❌ | 对话框、心愿、背包 |
| L4 覆盖 | 弹窗、Toast、命令面板 | ✅ | 仅重大事件横幅 | ✅ |

### 3.3 设计令牌（视觉统一）

在 `:root` 中整理出一套令牌，三种模式和昼夜只改令牌不改组件：

```css
/* 表面 */
--surface-1 / --surface-2 / --surface-3   /* 由 --glass、--glass-2 整理而来 */
--border, --shadow-sm, --shadow-lg
/* 文本 */
--text, --text-muted, --text-faint
/* 语义色 */
--accent（暖橙）, --sakura, --teal, --violet, --good, --bad
/* 尺寸 */
--r-sm 8px, --r-md 12px, --r-lg 16px, --r-pill 999px
--space-1..6 (4/8/12/16/24/32)
--hud-gap 12px, --topbar-h 56px, --dock-h 52px
/* 动效 */
--ease-out cubic-bezier(.2,.8,.2,1); --dur-fast 150ms; --dur 300ms
```

- **随时辰变化的界面色温**：`UI.frame` 已经知道当前分钟数，按 `skyAt()` 的结果给 `body` 设 `--tint`（清晨偏粉、正午偏白、黄昏偏橙、夜晚偏蓝紫），面板边框和高光轻微跟随。暗月界沿用现有 `body.moon-view` 的紫色主题。
- 尊重 `prefers-reduced-motion`：关闭镜头缓动、字幕打字机效果、面板滑入动画。

## 4. 🔭 观察模式（现有界面整理）

### 4.1 布局

```
┌──────────────────────────────────────────────────────────────────────┐
│ 🌸云溪镇  ☀️ 14:32 第3天·周五  🏮萤火节·还有1天  🎭张力42·伏笔   ⏸1×3×8× ⋯ │ ← 精简顶栏
├───┬──────────────────────────────────────────────────────────┬───────┤
│头像│                                                          │       │
│头像│                                                          │ 检查器 │
│头像│                   （小镇画布，≥70%）                        │（选中时│
│头像│                                                          │ 滑入） │
│ … │                                                          │       │
│   │                                                          │       │
├───┴──────────────┐                               ┌──────────┐│       │
│ 💬 动态  ▾（可折叠）│                               │  小地图   ││       │
└──────────────────┘   ┌─────────────────────────┐ └──────────┘└───────┘
                       │ 🔭 🎬 🎮 │ ⛅ 📢 📰 🕸️ 🛠 │  ← 底部 Dock
                       └─────────────────────────┘
```

### 4.2 改动要点

1. **顶栏瘦身**：只保留 品牌 · 时钟 · 状态标签 · 调速 · `⋯` 溢出菜单（声音、帮助、管理员、AI 大脑开关）。高度固定 `--topbar-h`，永不换行；空间不足时标签按优先级（故事 > 节日 > 区域）折叠进 `⋯`。
2. **底部 Dock**：居中悬浮，左段是模式切换（🔭 🎬 🎮），右段是工具（天气、事件、日报、关系、建设）。图标 + 悬停提示，移动端变成底部 Tab Bar。
3. **名册改为头像栏**：默认只显示 44px 头像竖列（带心情角标、思考光环、交谈描边），悬停展开成现在的卡片宽度。释放约 170px 横向空间。
4. **动态流**：默认折叠成一行「最新一条」的胶囊，点击展开为现在的面板；新增「📌 只看选中居民」过滤。重要条目（剧情、约定、抉择）在胶囊上短暂高亮。
5. **AI 大脑**：从常驻面板改为顶栏上的一个小圆点（颜色 = 空闲/思考中/错误，数字 = 队列长度），点击弹出现有的详情浮层。
6. **检查器**：
   - 宽度 400 → 360，头部固定，标签页改为可横向滚动的分段控件；
   - 新增「🔔 关注」按钮：被关注的居民发生对话/反思/约定时弹 Toast，并可在沉浸模式中提高其镜头优先级；
   - 在检查器打开时，小地图与 Dock 自动左移（替代现在 `right: 424px` 的硬编码）。
7. **命令面板** `Ctrl/⌘ + K`：输入居民名 / 地点名 / 功能名快速跳转（「苏墨」→选中并跟随，「图书馆」→镜头飞过去，「日报」→打开日报）。这是给信息越来越多的小镇的「万能入口」，实现成本低（本地过滤 `app.meta`、`app.spec.locations` 和固定命令表）。

## 5. 🎬 沉浸模式

目标：打开就能看，不需要任何操作；适合放在第二块屏幕、个人网站首页或直播。

### 5.1 画面

```
┌──────────────────────────────────────────────────────────────────────┐
│▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓（上黑边，可关）▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│
│  14:32 · 第3天 · 🌤                                  📍 月光酒馆   │ ← 3 秒后淡出
│                                                                      │
│                          （全屏小镇，自动运镜）                         │
│                                                                      │
│                                                                      │
│               林小满：「今晚的河灯……你会来吗？」                        │ ← 字幕
│               陈大山：「嗯，我帮你把灯芯剪好。」                          │
│▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│
└──────────────────────────────────────────────────────────────────────┘
```

- 隐藏 L2、L3 全部元素；L1 缩成左上角一行小字，每次镜头切换时淡入 3 秒再淡出。
- 可选 2.35:1 **电影黑边**（设置里开关，默认开）。
- 进入时请求 **全屏**（`requestFullscreen`，失败则忽略），自动开启环境音（需要一次用户手势，进入按钮本身就是手势）。
- 鼠标移动 / 触摸时，在底部浮出一条半透明控制条：`⏮ 上一个镜头 · ⏸ 锁定当前镜头 · ⏭ 下一个 · 🔊 · 字幕开关 · 退出`；2.5 秒无操作后隐藏，光标一并隐藏。

### 5.2 导演镜头（自动运镜）

新增 `public/js/camera.js`（纯前端），每 1 秒给候选镜头打分，选最高分目标：

| 候选 | 数据来源 | 基础分 |
| --- | --- | --- |
| 进行中的剧情场景 / 抉择 | `snap.story`、`log` 类型 `scene` `vote` `arc` | 100 |
| 异界生物遭遇 | `log` `encounter` `creature` | 90 |
| 双人/多人对话 | `snap.convos` | 60 + 参与人数 × 5 + 被关注加成 |
| 节日灯会 | `activeEvents` 中 `festival_lanterns` | 55（夜晚） |
| 新建筑施工 / 落地 | `worldmap` 事件、`entities` | 50 |
| 访客化身与居民互动 | `snap.avatars` 附近有人说话 | 45 |
| 独自行动的居民（内心独白） | `log` `thought` | 20 |
| 风景空镜（湖面、广场、日出日落） | 固定机位表 | 10（清晨/黄昏 ×3） |

规则：

- **最短停留** 8 秒、**最长停留** 40 秒；同一目标冷却 90 秒，避免来回跳。
- 分数差 > 40 时允许立刻切（例如裂隙张开）。
- 切换方式：距离近用**平移缓动**（复用 `app.follow` 的指数插值）；距离远先 **淡出到黑 250ms → 瞬移 → 淡入**，避免长距离横扫让人晕。
- 镜头缩放：对话时推近到 `zoom 2.0`，空镜拉远到 `1.0`，剧情场景根据参与者包围盒自动取景。
- 深夜（居民都在睡觉）进入「**夜景巡游**」：慢速在湖面、灯笼、萤火虫之间漂移，配合现有的夜晚光照。

### 5.3 字幕

- 对话气泡在沉浸模式下改为底部**字幕**（最多两行，逐字显示，说话人名字用其衬衫色 `look.shirt`）。世界内气泡保留但缩小为「…」省略号，避免与字幕重复。
- 内心独白用斜体 + 💭，旁白（剧情节拍、日报头条、天气变化）用居中衬线体（`Noto Serif SC`，已加载）。
- 字幕队列按时间排序，每条至少显示 `2s + 字数 × 90ms`。

### 5.4 章节卡

以下时刻全屏淡入一张「章节卡」2.5 秒，给挂机观看带来节奏感：

- 每天 06:00：「第 N 天 · 周X · 天气」；
- 日报出版：标题 + 头条（点击可展开全文）；
- 剧情弧阶段变化：「🌀 第二幕 · 爆发」；
- 抉择结果：结局名。

### 5.5 退出

`Esc`、双击画面、点击控制条「退出」都回到观察模式，镜头停在当前位置，并把当前目标设为选中居民（如果有）。

## 6. 🎮 游戏模式

目标：让访客**成为小镇的一员**，而不是隔着玻璃观看。

### 6.1 画面

```
┌──────────────────────────────────────────────────────────────────────┐
│ 👣 小月  ⭐ 3/12   ❤️ 认识 4 人          14:32 ☀️        ┌──────────┐ │
│                                                         │  小地图   │ │
│                                                         │ （我=★） │ │
│                    （镜头跟随我的化身）                     └──────────┘ │
│                                                          📜 今日心愿 │
│                      [E] 和 林小满 聊天                   · 帮孙婆婆  │
│                          🙂 ← 居民头顶的交互提示              找眼镜    │
│                        ★ 我                              · 去看萤火节 │
│                                                                      │
│ ┌──────────────────────────────────────────────┐  🎒  📖  🗺  ⚙︎      │
│ │ 林小满：你好呀，小月，第一次来吗？              │                    │
│ │ ▸ [输入框] 说点什么……                 发送 ⏎ │                    │
│ └──────────────────────────────────────────────┘                    │
└──────────────────────────────────────────────────────────────────────┘
```

### 6.2 进入流程

1. 点击 Dock 的 🎮（或按 `G`）。
2. 没有化身 → 显示**全屏角色卡**（替代现在的化身弹窗）：名字、8 色衣服、预览小人实时换色、一句「来小镇的理由」（可选，会作为居民对你的第一印象写入记忆——需服务端支持，见 §8）。
3. 已有化身 → 镜头飞到化身，锁定跟随。

### 6.3 移动

| 输入 | 行为 |
| --- | --- |
| 点击地面 | 走到该格（寻路走到最近可达格） |
| 点击建筑 / 地点名 | 走到该地点门口（沿用现有 `/api/avatar/move`） |
| `WASD` / 方向键 | 按住持续朝该方向走一格一格（观察模式下仍是平移镜头） |
| 移动端 | 左下虚拟摇杆 + 点地 |

- 目标点显示一个淡出的落点圆圈；路径用虚线预览（前端 A*，地图数据已在 `app.world` 中）。
- 镜头：化身位于屏幕中下 40% 处的**松弛跟随**（死区 3 格，超出才移动），比观察模式的硬跟随更舒服。

### 6.4 与居民互动

- **接近提示**：化身 2 格内的居民头顶出现 `💬` 图标，最近的一位显示 `[E] 和 XX 聊天`；点击居民本身也可以。
- **对话框**：底部 RPG 式对话框，替代检查器里的「交谈」标签：
  - 居民回复逐字出现，头像 + 名字 + 当前心情；
  - 输入框常驻，`Enter` 发送；配额提示（`chatquota`）挪到输入框右侧小字；
  - 右上角「💭 化作心声」切换，用不同底色区分（紫色）；
  - 居民走开 / 你走开超过 4 格时自动结束对话，并提示「XX 去忙别的了」。
- **旁听**：走到正在对话的居民旁边，其对白以字幕形式出现（只读），满足「偷听八卦」的乐趣。
- **送礼**（第二阶段）：背包里的物品拖到居民身上。依赖服务端新增访客物品，先不做。

### 6.5 轻量游戏化（全部基于已有数据，只在前端计算）

| 系统 | 数据来源 | 呈现 |
| --- | --- | --- |
| **📜 今日心愿** | 居民的 `todayGoal`、剧情线程看板（`/api/story` 的 threads）、正在进行的抉择 | 右侧 3 条可追踪任务；点「追踪」在小地图上标出相关地点/居民；完成条件用简单规则判断（例如「与 X 交谈过」「在节日时身处镜湖」「在抉择中投过票」） |
| **❤️ 相识** | 本机记录与哪些居民聊过、次数 | 顶部「认识 N 人」；每位居民卡片显示「初识 / 熟人 / 朋友」三档（按对话次数，前端计） |
| **⭐ 足迹与图鉴** | 到过的地点、见过的生物（`spec.creatures`）、参加过的节日、见证的剧情节拍 | 📖 图鉴面板，已收集的点亮，未收集的显示剪影；复用现有 `creatureFace()` |
| **🗳 参与** | 投票、事件提议、建设建议 | 在游戏模式中以「任务完成」的形式反馈，而不是只弹一个 Toast |
| **🏅 成就** | 以上各项的里程碑 | 解锁时右上角滑出徽章，存 `localStorage['town-progress']` |

原则：**游戏化只奖励「参与小镇生活」，不奖励刷量**——不做排行榜、不根据聊天次数给数值奖励之外的东西，避免诱导刷接口。所有计数与限流保持现状。

### 6.6 退出

`Esc` 弹出小卡片：「留在小镇（化身继续站在原地，20 分钟无操作自动离开）」/「离开小镇」/「取消」。

## 7. 移动端

| 断点 | 策略 |
| --- | --- |
| ≥ 1200px | 如上设计 |
| 900–1199px | 名册只显示头像；检查器 340px；动态流默认折叠 |

另外补齐 `safe-area-inset-*`（`index.html` 已声明 `viewport-fit=cover`，但 CSS 未使用）。

## 8. 需要的服务端改动（仅游戏模式）

观察和沉浸模式**完全不需要改服务端**。游戏模式需要：

| # | 接口 | 说明 | 是否必须 |
| --- | --- | --- | --- |
| S1 | `POST /api/avatar/goto { x, y }` | 走到任意可达格（现在只能按地点 id 走）。服务端校验可达性、区域权限，沿用 `move` 已有的 `MOVE_CD_MS` 冷却。`AvatarSystem.walk` 已用 `findPath` 寻路，只需增加「目标是格子」的分支 | 必须 |
| S2 | tick 的化身视图附带剩余 `path` 的下一两个点 | 前端可预览路径、插值更平滑（服务端已有 `v.path`，只是没下发） | 建议 |
| S3 | `POST /api/avatar { ..., intro }` | 「来小镇的理由」作为居民对化身的第一印象记忆，走现有审核 | 可选 |
| S4 | `GET /api/avatar/near` 或在 tick 中附带 `nearAvatar` | 服务端判断「在面前」的依据与前端一致，避免前端显示可聊天、服务端却认为不在身边 | 建议（也可以直接复用 `AvatarSystem.near` 的半径常量，前后端共用 6 格） |

所有新接口沿用现有的 `X-Visitor` 身份、按 IP 限流和 `allowInteraction` 检查。

## 9. 前端工程方案

保持零依赖、零构建，按职责拆分 `ui.js`（现 996 行）：

```
public/js/
  main.js          入口：数据流、主循环（相机更新改为调用 camera.js）
  render.js        渲染：新增 setOverlay({ letterbox, subtitles:false, dim }), drawPathPreview(), drawInteractHint()
  camera.js        新：手动 / 跟随 / 松弛跟随 / 导演镜头 四种相机策略
  modes.js         新：app.mode 状态机、body[data-mode]、快捷键映射、全屏、URL 参数
  hud/
    topbar.js      顶栏与溢出菜单
    dock.js        底部 Dock / 移动端 Tab Bar
    roster.js      名册（从 ui.js 拆出）
    inspector.js   检查器（从 ui.js 拆出）
    feed.js        动态流（从 ui.js 拆出）
    brain.js       AI 状态点与浮层
    palette.js     新：命令面板
  immerse/
    subtitles.js   新：字幕队列
    chapters.js    新：章节卡
  play/
    controls.js    新：点地 / 键盘 / 摇杆移动
    dialog.js      新：RPG 对话框（复用现有聊天接口）
    quests.js      新：心愿、相识、图鉴、成就（纯前端 + localStorage）

```

- CSS：`style.css` 拆为 `tokens.css`、`hud.css`、`modals.css`、`modes.css`，用 `@import` 或在 `index.html` 中并列引入；模式差异尽量写成 `body[data-mode="immerse"] #roster { … }` 这类选择器。
- 相机策略统一接口：`update(dt, S) → { x, y, zoom }`，主循环只调用当前策略，替代 `main.js` 里散落的跟随、键盘平移逻辑。

## 11. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 拆分 `ui.js` 时引入回归 | U1 只做搬移不改行为；用 Playwright（环境已有 Chromium）对三种屏幕宽度截图对比 |
| 导演镜头频繁切换让人头晕 | 最短停留、冷却、远距离用淡入淡出；提供「锁定镜头」 |
| 游戏模式点地移动放大请求量 | S1 沿用 `MOVE_CD_MS` 冷却；前端合并连续点击，只发送最后一次 |
| 游戏化诱导刷聊天、消耗令牌 | 不设数值奖励排行；心愿以「去某处 / 见证某事」为主，聊天类心愿每天最多 1 条；限流与每日预算保持不变 |
| 沉浸模式长时间挂机消耗额度 | 沿用现有「无人观看自动休眠」逻辑；沉浸模式的页面仍算作观看者，这是预期行为，在帮助里说明 |
| 全屏 / 自动播放音频被浏览器拦截 | 都放在用户点击的回调里；失败静默降级 |
