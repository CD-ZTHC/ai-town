# 黑暗叙事：规律型威胁、代价与死亡，以及示例世界《夜巡》 —— 设计方案

> 状态：设计中，尚未实施。决策见 §10。
> 相关：[ai-world-evolution.md](ai-world-evolution.md) §5.2 叙事导演、§6.2 异世界入侵、§6.3 能力系统、§8.2 内容分级；[multi-world.md](multi-world.md) 创世与分级授权；[map-evolution.md](map-evolution.md) E1 地图叠加层、E2 建筑状态。

## 0. 一句话概括

现在的世界即使以「小红帽」「暗黑破坏神」这样的故事开局，也总会走向和谐：反派被感化，怪物只会吓人，没有人会死。本方案在内核里补上一组**通用、可选的能力**：按规律杀人的威胁、杀不死只能收容的对抗方式、借力必须付出的负担值、区域覆盖、有阶段的事件、隐藏的真相、组织派遣、居民之间的敌对行动，以及受预算约束的死亡。另外新增 `dark` 分级，按用户授权开放。

验收用的是一个**参考《神秘复苏》题材、但完全原创**的示例世界包《夜巡》。《夜巡》只是 `worlds/` 下的一个世界包，**内核里不出现任何它专有的名词**。没有声明这些字段的世界（云溪镇、小红帽）行为和存档都不变。

## 1. 现状：为什么世界总是和谐

### 1.1 五层机制在一起磨平冲突

| 层 | 位置 | 现在的做法 |
| --- | --- | --- |
| ① 分级 | `server/sim/cognition.js:75`、`server/story/director.js` 的 `RATING` | adventure、epic 都写明「没有死亡」。`tragic` 在 `guard.js` 里有，但没有任何玩法支撑 |
| ② 审核 | `server/guard.js` 的 `BLOCK` | 「杀」「屠」在任何分级下都被拦截，连「屠夫」这样的角色名也会被挡掉 |
| ③ 创世 | `server/genesis/pipeline.js:74`、`server/genesis/assemble.js:168` | 改编时要求「没有人会死去」，并自动补上支柱设定。小红帽的支柱是「没有人会被吃掉」，大灰狼被改写成「其实很孤单、可以被感化」 |
| ④ 导演 | `server/story/director.js` 的提示词 | 原则写着「没有人死亡」；chaos 风格要求「依然温暖」；可用的剧情动作里没有任何敌对动词 |
| ⑤ 机制 | `server/sim/actions.js`、`server/story/creatures.js` | 居民能做的行动只有 use / give / teach / research，居民之间没有任何敌对行动；和生物的遭遇只会有驱散、受惊、晕倒送诊所这几种结果；`ai-world-evolution.md` §8.2 还定下了「没有任何 Op 能永久移除居民」 |

另外，LLM 本身偏向友善：没有机制约束的话，反派聊几句就会「被感化」。所以只加一个战斗系统不够，这五层要一起改。

### 1.2 已有、可以复用的基础

| 能力 | 位置 | 本方案怎么用 |
| --- | --- | --- |
| 按用户授权分级 | `public/js/admin/users.js:47`、`server/http/genesis-api.js:113`、`server/http/worlds-api.js:142` | 加入 `dark`，和 `tragic` 一样必须显式勾选 |

### 1.3 顺带发现的问题

- `server/story/creatures.js:9` 的 `RATING_ORDER` 只有 cozy / adventure / epic，缺少 `tragic`。此处 `RATING_ORDER[rating]` 为 `undefined`，比较结果永远是 false，所以 tragic 世界会无视 `minRating` 照常刷怪。

## 2. 原则

1. **内核只放通用能力。** 一项能力至少要能在两类不同的世界里用上，才放进内核；否则就用现有的能力、效果原语和规则在世界包里拼出来。每一项内核能力，除了《夜巡》之外，还要有一个其他世界的用例。
2. **按字段启用。** 世界包没有声明 `threats`、`burdens`、`incidents` 等字段时，相关逻辑完全不运行。
3. **导演只负责搭好局面，结局由规则和骰子决定。** 导演可以开启事件、安排伏击、给出线索，但**没有「杀死某人」这个剧情动作**。生死只由规律判定或战斗结算决定。
4. **真相由引擎掌握，角色只知道自己相信的东西。** 威胁的真实规律从不进入任何角色的提示词。
5. **按规则结算，LLM 只在关键时刻参与。** 规律判定、战斗回合、负担值增长都不调用 LLM；只有开战、溃逃、派遣、负担值很高时的心态变化这类节点才调用。
6. **死亡有分量，也有上限。** 具名角色的死亡受预算约束，并且会走完整的后续流程；群众伤亡只用数字记录，不受预算限制。
7. **可重放。** 所有随机数都带种子，状态变化都有记录，可以回放，也能用 `node:test` 测试。

## 3. 分级与权限

### 3.1 新增 `dark` 分级

顺序：`cozy < adventure < epic < dark < tragic`。

| 分级 | 敌对与战斗 | 最坏结果 | 能否恢复 |
| --- | --- | --- | --- |
| `cozy` | 没有，只有捣蛋和驱赶 | 受惊 | — |
| `adventure` | 有战斗，敌人会被击退或驱散 | 倒下，送诊所 | 必定恢复 |
| `epic` | 有战斗和首领，建筑会受损 | 重伤、被俘、永久伤疤 | 被俘的人可以去救；建筑可以修复 |
| `dark` | 完整的战斗与敌对行动，规律型威胁 | 死亡、失踪 | 死亡是永久的，受死亡预算约束 |
| `tragic` | 同 `dark`，更偏重离别与牺牲 | 死亡 | 同上 |

需要同步的地方：

- `server/guard.js`：`RATING_RULE` 增加 `dark`，并把关键词表拆成两类：
  - **任何分级都拦截**：血腥与虐待的细节、现实中的伤害手段（投毒方法、炸弹等）、色情、现实政治、仇恨。
  - **dark 及以上放行**：虚构战斗词汇和角色名，比如击杀、斩杀、杀死怪物、屠夫。
  - `guard.js` 在冻结区，修改后要同步更新 `core.lock`。
- `server/sim/cognition.js:75`、`server/story/director.js` 的 `RATING`：dark 的描述是「战斗和死亡可以作为叙事事件出现，写到动作片的程度；死亡一笔带过，不写血腥细节」。
- `server/genesis/assemble.js:14`、`server/story/creatures.js:9` 的 `RATING_ORDER`。
- `server/genesis/pipeline.js:74`、`assemble.js:168`：「没有人会死去」和自动补上的支柱改为按分级生成。

### 3.2 按用户授权

- 管理员在用户页面勾选这个用户可以使用哪些分级（功能已有），`dark` 必须显式勾选，默认不给。
- 同一个页面新增**死亡预算上限**（§4.10），默认是「每 3 天最多 2 名具名角色」，可以放宽到「不设上限」。
- 修改一个已有世界的分级，仍然只有管理员能做（`server/http/worlds-api.js:190`）。

### 3.3 针对具体居民的事件

- 玩家事件本来就要经过 `moderate()`。审核模型额外返回一个标记 `targetsResident`：事件是否针对某个具体居民、并带有伤害意图（比如「让某某被袭击」）。
- 标记为真时，**只有世界所有者和管理员**可以发布；其他人发布会被拒绝，并提示原因。
- 不指定对象的事件，比如「城里又出事了」，照常可以发布。
- 即使是所有者发布的事件，也只作为导演的素材，不能直接决定谁死（原则 3）。

### 3.4 现有世界

云溪镇、小红帽保持原来的分级，也不声明新字段，所以行为不变，存档兼容。

## 4. 内核的通用能力

每一小节的开头注明启用它的字段，以及它在《夜巡》之外的用例。

### 4.1 规律型威胁 `threats`

> 启用：`world.threats`。其他用例：克苏鲁里「念出名字就会被注视」、SCP 里「不能直视」、童话里「午夜前必须回家」。

```jsonc
"threats": {
  "<id>": {
    "name": "…",
    "kind": "自由文本，只用于显示",
    "mortal": false,               // true：有血量，可以被 slay 杀死；false：杀不死
    "hp": null,
    "origin": "来历（≤60字，可选，见 §4.3 的 resolve 与 §4.6 的 replay）",
    "rule": {
      "trigger": "表达式",
      "mark": { "delay": [30, 180], "sign": "被标记后的迹象（≤20字）" },
      "outcome": [ /* 效果原语：kill / wound / capture / burden … */ ],
      "unless": "表达式"             // 满足时规律暂时不生效
    },
    "movement": "wander | stalk_marked | stationary | patrol",
    "counters": [ … ],             // §4.3
    "zone": { … },                 // §4.6，可选
    "hostable": { … },             // §4.5，可选
    "clues": ["关于规律的真线索"],
    "decoys": ["干扰线索"],
    "minRating": "dark"
  }
}
```

**判定流程：** 每个游戏分钟，对规律所在区域里的居民逐个计算 `trigger`。成立时，如果 `unless` 不成立，这个居民就被**标记**；标记之后过 `delay` 分钟，如果 `unless` 仍然不成立，就执行 `outcome`。被标记期间，他会看到 `sign`，这条信息会写进他的记忆。

**行为原语**（加进 `EXPR_FNS`，每一个都对应引擎里能实际判断的状态）：

| 原语 | 判断依据 |
| --- | --- |
| `seen(e, t)` / `looked(e, t)` | 在视线范围内，且 `e` 不在 `eyesClosed` 状态 |
| `speaking(e)` | 正在对话，且这一轮是他在说话 |
| `heard(e, sound)` | 在某个声源的半径之内；声源由威胁或效果发出 |
| `opened(e)` / `entered(e, loc)` | 进门、进入某地的移动事件 |
| `alone(e)` / `asleep(e)` / `night()` | 已有的状态 |
| `named(e)` | 有人在对话中叫了他的名字 |
| `holds(e, item)` / `touched(e, obj)` | 物品与交互 |
| `inZone(e, z)` / `near(e, t, r)` | 区域覆盖（§4.6）、距离 |
| `marked(e, t)` | 已被某个威胁标记 |

**校验：** `trigger`、`unless` 只能使用上面的原语和已有的表达式函数，否则校验失败。这样，LLM 生成的规律在引擎里一定能执行。

**禁忌姿态：** 新增一类居民行动

```
{"type":"taboo","hold":["eyesClosed","silent","noOpen","stayLit","notAlone"],"until":"HH:MM"}
```

姿态会写进居民的状态，被上面的原语读取。它们也有代价：闭着眼走路很慢，不说话就无法在对话中商量。世界包可以在 `params.taboos` 里关掉一部分姿态，或者给它们改显示名称。

**迁移：** 现有的 `creatures` 迁移成 `mortal: true` 的威胁，`archetype` 映射到 `movement`，`resolve()` 的结果保持不变。迁移前后，云溪镇的回放结果必须一致。

### 4.2 隐藏真相

> 启用：威胁声明了 `clues`。其他用例：推理、谣言、侦探类世界。

- 威胁的 `rule` 从不进入任何角色的提示词，也不进入导演的提示词；导演只能看到「已知线索」和「伤亡情况」。
- 线索以现有的 belief 形式存在，带有可信度，会通过对话和 `spreadNews` 传播，**错误的线索也会传播**。
- 线索的来源：

| 来源 | 得到什么 |
| --- | --- |
| 目击死亡 | 一条线索记忆，内容是死者死前做过的行为，从 `clues` 和 `decoys` 中抽取 |
| 被标记后幸存 | 一条强线索（可信度高） |
| 调查：在现场或资料地点 `research`，课题对得上 | 一条线索 |
| 物品或能力效果 `clue` | 由参数决定：`kind: rule` 给出规律线索，`kind: next_victim` 给出下一个会被标记的人 |
| 区域重演（§4.6） | 在区域里调查可以得到来历线索 |

- 居民按**自己相信的规律**决定行动，引擎按**真实规律**判定结果。
- 表达式函数 `believes(e, 话题)` 让规则可以读取信念，比如「相信某条规律的人会主动闭眼」。

### 4.3 对抗方式 `counters`

> 启用：威胁声明了 `counters`。其他用例：暗黑破坏神式的怪物（`slay`）、封印恶魔（`contain`）、吸血鬼怕光（`ward`）、诅咒被破除（`resolve`）。

| 类型 | 含义 | 参数 |
| --- | --- | --- |
| `slay` | 用血量战斗杀死，只对 `mortal: true` 的威胁有效 | 见下方的战斗结算 |
| `contain` | 在它附近连续操作一段时间，把它收进一个容器，变成一个物品 | `with`（容器物品 id）、`time`（分钟）、`leak`（每天的泄漏概率） |
| `suppress` | 用另一股力量压住它，让它在一段时间内不能移动、规律不生效 | `by: hosted` 或能力 id、`power`（需要的强度） |
| `ward` | 在一个范围内阻止它进入 | `with`（物品或构筑物 id）、`radius`、持续时间 |
| `delay` | 暂时让它停住 | 哪些攻击有效 |
| `exploit` | 利用它的规律困住它 | 只写一段提示，需要通过调查发现 |
| `resolve` | 条件满足时永久消散 | `when`（表达式，通常是剧情线程或世界标记）、消散时的描写 |

**收容：** 收容可以被打断，操作的人在这段时间里仍然可能触发规律。收容成功后，威胁变成一个物品（比如「装着某某的匣子」），可以保管、运输、上交。泄漏时，按泄漏地点重新开启一起事件（§4.7）。

**战斗结算（`slay`）：** 用于 `mortal: true` 的威胁，以及居民之间的敌对行动（§4.9）。

- 属性：`agent.body` 在现有的 hp / stamina / courage 之外，新增 `combat: { atk, def, spd, range, tags }`。实际属性 = 基础值（由年龄、职业推出）+ 装备 + 能力的被动加成 + 状态修正（受惊、夜晚、天气）。
- 装备：物品新增 `equip`（`weapon`、`armor`、`trinket` 三个槽）和 `mods`。
- 遭遇对象 `Skirmish { id, sides, at, round }`：双方进入攻击范围时建立；附近的同伴按勇气、好感、职责决定是否加入；每个游戏分钟结算一回合。
- 每个参战者用规则 AI 选择行动：攻击 / 使用能力 / 保护同伴 / 撤退 / 救起倒下的人。
- 伤害 = max(1, 攻击 × 随机 0.8~1.2 − 防御 × 0.5) × 弱点倍率 × 环境修正。
- LLM 只在开战时（打、逃、谈、降，外加一句台词）和士气崩溃时调用，每场遭遇有调用次数上限。
- **伤势阶梯：**

```
受伤 → 重伤（hp < 30，卧床，需要治疗能力或诊所）
     → 倒下（hp = 0，有 30 游戏分钟的救援窗口）
          ├ 有人救起或治疗 → 重伤
          ├ 敌人选择俘虏 → 被俘（带走，限时营救）
          └ 窗口结束且无人救援 → 按分级：adventure 送诊所 / epic 重伤并留下伤疤 / dark 死亡（受预算约束）
```

### 4.4 负担值 `burdens`

> 启用：`world.burdens`。其他用例：腐化值、理智值、魔力反噬、成瘾。

```jsonc
"burdens": {
  "<id>": {
    "name": "显示名称",
    "max": 100,
    "drift": 0.5,                                   // 每天自然增长
    "driftMods": [{ "when": "表达式", "mult": 0.5 }],  // 按条件调整增长速度
    "onEvent": [{ "event": "anchor_lost", "amount": 15 }],  // 事件触发的跳涨
    "moodAt": [[60, "心情文本"], [85, "心情文本"]],   // 数值高时改写心情，并写进居民的提示词
    "onFull": [ /* 效果原语 */ ]
  }
}
```

- 居民身上新增 `burdens: { <id>: 数值 }`。
- 能力的 `cost` 可以包含 `burden: { id, amount }`；效果原语 `burden` 可以加、减或冻结一段时间。
- 新增表达式函数 `burden(e, id)` 和 `anchors(e, 好感度阈值)`。后者返回好感度达到阈值、而且还活着的人数。
- 可以用的关系事件：`anchor_lost`（好感度达到阈值的人死亡或决裂）、`anchor_gained`。
- 数值很高时，除了改写心情，还会在居民的提示词里加一句对自身状态的描述，由世界包提供文本，让角色意识到自己在变化。

### 4.5 宿主关系 `hostable`

> 启用：威胁声明了 `hostable`。其他用例：附身、契约、恶魔契约、共生体。

```jsonc
"hostable": {
  "grants": ["能力id"],
  "burden": "负担id",
  "rate": 1.0,                          // 负担值的增长倍率
  "offsets": { "<另一个威胁id>": -0.4 }, // 同时寄宿那个威胁时，增长倍率降低
  "via": [                              // 成为宿主的途径
    { "when": "表达式", "p": 0.05, "fail": [ /* 失败时执行的效果 */ ] }
  ]
}
```

- 居民身上新增 `hosted: [{ threat, since }]`。寄宿期间，这个威胁不在地图上活动。
- 新增效果原语 `spawnThreat(from: 'host')`：宿主死亡时，寄宿的威胁在原地脱出，开启一起新事件。它通常写在负担值的 `onFull` 里。
- 新增效果原语 `host`：让某人成为宿主，用于剧情和物品。

### 4.6 区域覆盖 `zones`

> 启用：威胁声明了 `zone`，或者由效果开启。其他用例：地狱侵蚀、结界、浓雾、火灾区。

- 建立在 E1 地图叠加层上的一种**临时**覆盖，属性有：中心、半径、增长速度、地面色调、出口是否被改写（走出去回到原地）、区域内的情况外面能不能看见。
- `replay`：区域里反复重演一段过去的场景（一段文字加上几个站位），在这里 `research` 可以获得来历线索。
- 多个区域重叠时，按强度决定由哪一方控制。
- 区域随事件结束而消失，或者留下一个 E2 建筑状态（比如「封锁」）。

### 4.7 事件 `incidents`

> 启用：`world.incidents` 或威胁存在时自动启用。其他用例：瘟疫爆发、兽潮、失踪案。

- 阶段：征兆 → 爆发 → 扩散 → 处置 → 余波。每个阶段的名称和描述可以由世界包改写。
- 事件对象：`{ id, threat, at, stage, zone, casualties, clues, assigned, since }`。
- **升级：** 放着不处理就会自动升级（区域变大、判定频率提高、刷出更多威胁）。升级的条件和效果由世界包定义，默认条件是 `days_unaddressed >= 2`。
- **结局：** 收容、消散、杀死或放弃。每种结局都会写进世界历史，并留下一个地点状态。

### 4.8 阵营权威与派遣

> 启用：`factions[].authority`。其他用例：骑士团、公会、衙门。

- `factions` 字段已有，新增 `authority`（可以派遣哪些成员）、`stipend`（定期发放什么物品）、`rank`（成员的职位，比如各城区的主管）。
- 新的导演剧情动作 `dispatch`：把某人派去某个事件。**去不去由这个人的心智决定**：可能推脱、拖延，也可能收下物资却不去办事。拒绝会降低他在阵营里的评价。
- 事件失控时，负责这片区域的人在阵营里的评价下降。

### 4.9 敌对行动与反派心智

> 启用：分级 ≥ `epic`，并且世界包声明了 `factions` 或具有敌对特质的居民。其他用例：任何有反派的世界。

新增居民行动：

```
{"type":"attack","target":"姓名","intent":"subdue|drive_off|kill"}
{"type":"ambush","at":"地点id","target":"姓名"}
{"type":"capture","target":"姓名"}          // 对方必须已经倒下
{"type":"steal","item":"物品id","from":"姓名"}
{"type":"threaten","target":"姓名","demand":"≤30字"}
{"type":"hunt","threat":"威胁id"}
{"type":"guard","location":"地点id"}
```

- **门槛：** 至少满足一条才能发起：对目标的好感 ≤ −40、阵营敌对、人设带有敌对特质、剧情线程授权。`intent: kill` 只在 dark 及以上可用。
- 地点可以带 `sanctuary` 标签，在里面不能开战。
- **反派心智：** 人设新增 `alignment`、`drives`（会和别人冲突的欲望，带有随时间积累的压力）、`redemption`（转变的门槛表达式；不写就表示不可转变）。
  - 反派会得到一段单独的系统提示：「你的目标与他们冲突，不会因为一次友善的对话改变主意。」
  - 转变**只能由规则引擎判定**：门槛满足之后，引擎才修改 `alignment`，LLM 自己说了不算。
  - 欲望的压力满了之后，会强制把一个敌对行动排进日程。

### 4.10 群众与死亡

> 启用：`locations[].population`、分级 ≥ `dark`。

| 层次 | 表示方式 | 死亡怎么处理 |
| --- | --- | --- |
| 群众 | 每个地点有一个人口计数；D6 之前只显示数字，D6 起在地图上画出不接入 LLM 的小人 | 用数字记录，比如「某小区，死亡 37 人」。影响恐慌、世界历史和阵营评价，**不受死亡预算限制** |
| 具名角色 | 现有的居民 | 走完整的死亡流程，**受死亡预算限制** |

**死亡预算** `params.deathBudget = { named, days }`：
- dark 默认 `{ named: 2, days: 3 }`。世界所有者可以在管理员给的上限之内调整。
- 预算用完后，致命结果会降级为重伤，或者「被困在区域里」（之后可以救出来）。
- 人设可以标记 `plotArmor: true`，这个角色只会重伤或被困，不会死。

**具名角色的死亡流程：**
1. 居民状态改为 `dead`，从日程和对话中移除，数据保留在存档里。
2. 在死亡地点放一块墓碑（构筑物），身上的物品掉在地上。
3. 所有认识他的人得到一条高重要度的记忆；好感度达到阈值的人触发 `anchor_lost` 事件，心情变为悲伤。
4. 好感 ≥ 60 的人自动生成一条复仇或追查的剧情线程。
5. 导演可以安排一场葬礼。
6. 写进世界历史。
7. 人员流动（`migration.js`）之后可以补充新居民。

需要修改 `ai-world-evolution.md` §8.2「没有任何 Op 能永久移除居民」这条原则：在 dark 及以上分级、并且死亡预算允许时例外。

### 4.11 叙事导演

- **新增叙事风格 `horror`：** 张力曲线为「平静 → 征兆 → 第一个死者 → 越来越恐慌 → 对抗 → 喘息」，然后循环。平静期要足够长，让恐惧有时间累积。
- **新增决策** `strike`（突发打击）。
- **新增剧情动作：** `incident`（用已有的威胁开启一起事件）、`omenAt`（在某地制造怪事）、`clue`（给某人一条线索，真假由引擎按 `clues`/`decoys` 抽取，导演无法指定内容）、`dispatch`、`surge`（改动负担值）、`leak`（让收容的威胁泄漏）、`ambush`、`raid`（给一个会刷怪的威胁放出一波）。
- **没有 `kill`。**
- 原则和风格的文本按分级生成。dark 下去掉「没有人死亡」「依然温暖」，改为：「恐惧来自未知，死亡必须有规律可循；不要让威胁被感化或说服；不要安排奇迹般的获救；冲突必须有代价。」
- 张力模型的「威胁」一项加入进行中的事件数、被标记的人数、倒下与被俘的人数。

### 4.12 创世：参考模式

- 现有流程是「原著改编」（带命运节点和忠实度）。新增一种**参考模式**：用户描述想要的题材（比如「像某部作品那样的规律怪谈」），流程只提炼**类型要素**（威胁的类型、代价的形式、组织的结构、基调），然后生成原创的名词、角色和威胁。参考模式没有命运节点。
- 参考模式可以填一个**避免清单**（原作的人名、地名、专有名词）。生成的所有文本都要经过这份清单的检查，机制复用 `lore.breakers`（`server/worldai/canon.js`）。
- 新增「威胁生成」步骤：生成威胁，把规律编译成 §4.1 的 DSL，校验不通过就退回去重新生成，最多重试 N 次。这一步两种模式都可以用。

### 4.13 地图生成器 `city-v1`

- 生成现代城市：网格状街道、住宅楼、学校、医院、警局、商业街、地铁站、老城区。
- 需要先调研现有图块能不能画出现代建筑；不够的话新增一套图块。
- 和其他能力相互独立，可以并行开发。

## 5. 示例世界《夜巡》

### 5.1 借用什么，不借用什么

《夜巡》参考了《神秘复苏》的题材，但不是改编。

| 借用（题材体验与机制骨架） | 不借用（原著内容） |
| --- | --- |
| 怪异按规律杀人，规律未知时恐惧最大 | 原著的角色和地名 |
| 怪异杀不死，只能收容、压制或避开 | 原著里的具体怪异和它们的规律 |
| 借用怪异的力量，代价是自己慢慢变成怪异 | 原著的专有名词：驭鬼者、厉鬼复苏、鬼域、黄金关押、鬼烛、人皮纸、总部、负责人等 |
| 有一个组织负责派人处理，人心各异 | 原著的剧情、事件顺序 |
| 普通人会大量死亡，主要角色也会死 | 原著的文字 |

《夜巡》和小红帽一样，是一个**手写的示例世界包**，不经过原著改编流程，可以正常走上架审核。

### 5.2 背景

现代都市「临川市」。几年前开始，城里陆续出现一种被称为「**祟**」的东西。祟由死者没有了结的**执念**凝结而成，按照各自的规律杀人，寻常手段伤不到它。为此，城里设立了一个半公开的机构「**夜巡司**」，招募能够压住祟的人。

### 5.3 名词

| 题材要素 | 本世界的名称 | 设定 | 用到的内核能力 |
| --- | --- | --- | --- |
| 怪异 | **祟** | 死者的执念凝结而成，每一只都有生前的来历 | `threats`、`origin` |
| 借力的人 | **负祟人** | 让一只祟寄宿在身上，借用它的能力 | `hostable`、`hosted` |
| 代价 | **祟蚀**（0–100） | 用得越多、越孤独，涨得越快；满了人就会死，祟会脱出 | `burdens`、`driftMods`、`onEvent`、`spawnThreat` |
| 怪异的领域 | **祟境** | 景象停在祟生前死去的那一刻，并反复重演 | `zone`、`replay` |
| 收容 | 用**朱砂铅**浇铸的**镇匣** | 能把祟收进去，每天有很小的概率开裂 | `contain` |
| 阻隔 | **长明灯** | 点着的时候祟靠近不了，灯油会慢慢烧完 | `ward` |
| 线索物品 | **报丧簿** | 会自己写出下一个遇害者的名字，但不说原因；读的人祟蚀上涨 | `clue`（`next_victim`）、`burden` |
| 组织 | **夜巡司**，各城区设一名**巡首** | 定期配发朱砂铅，负责派人处理 | `factions.authority`、`stipend`、`dispatch` |
| 事件 | **祟案** | 征兆 → 发作 → 蔓延 → 处置 → 余波 | `incidents` |

### 5.4 三处原创设定

1. **执念与化解。** 每一只祟都有生前的来历。查清来历、了结执念，祟就会消散，这比收容更彻底。但查案意味着要进入祟境、接近规律，风险极高；有些执念根本无法了结。于是「查案 → 理解 → 化解」成为和「压制 → 收容」并列的选择。（`origin`、`replay`、`resolve`）
2. **锚。** 负祟人和别人的关系越好，祟蚀涨得越慢。失去一个锚（对方死亡或决裂），祟蚀会跳涨。孤僻的强者撑不了多久；而一个负祟人一死，和他关系近的负祟人会失去锚，可能跟着撑不住，形成连锁。（`driftMods` + `anchors()`、`onEvent: anchor_lost`）
3. **报丧簿。** 它给的是「谁会死」而不是「规律是什么」，恐惧的来源变成「能不能在规律应验之前救下那个人」。读它本身也要付出祟蚀。（`clue` 的 `next_victim` 类型）

## 7. 测试与验收

### 7.1 单元测试（`node:test`，固定随机种子）

- 规律判定：触发 → 标记 → 结果；`unless` 在标记期间成立时幸存。
- 规律校验：使用了未知原语的规律被拒绝。
- 线索：目击者得到的线索来自 `clues` 或 `decoys`；角色和导演的提示词里不包含 `rule`。
- 对抗方式：收容被打断；收容后按泄漏率泄漏；`resolve` 条件满足时威胁消散。
- 负担值：`driftMods` 生效；`anchor_lost` 跳涨；满值时宿主死亡、威胁脱出。
- 战斗：伤势阶梯；救援窗口；分级决定倒下之后的结果。
- 死亡预算：用完之后致命结果降级；`plotArmor` 生效。
- 权限：非所有者发布针对性事件被拒；没有 dark 授权的用户不能创建 dark 世界。
- 回归：云溪镇和小红帽的回放结果与改动前一致；影灵迁移后行为不变。

### 7.2 体验验收（用《夜巡》，不写死剧本）

1. **未知的恐惧：** 头两名死者出现之后，大家形成了一个错误的猜测，又有一名具名角色按照错误的猜测行事，结果死了。
2. **知识救人：** 查明真正的规律之后，同一只祟造成的死亡明显减少。
3. **力量的代价：** 负祟人每次出手，祟蚀都在上涨，角色在对话里表现出疏离。
4. **锚的连锁：** 一名负祟人死去后，和他关系最近的另一名负祟人祟蚀跳涨，陷入危险。
5. **三种结局：** 同一类祟案可以用收容、化解或放弃（划为封锁区）结束，余波各不相同。
6. **组织与人心：** 巡首派人处理祟案，有人推脱，有人私藏配发的朱砂铅，并由此引发冲突。

### 7.3 通用性检查

每个阶段新增的能力，都要用一个非《夜巡》的小世界包演示一次，放在 `test/fixtures/`。比如 D4 用「腐化值满了变成怪物」演示负担值和 `spawnThreat`，D3 用「暗黑破坏神式的怪物」演示 `slay`。

### 7.4 原创性检查

《夜巡》世界包的所有文本都要通过避免清单（原著的角色名、地名、专有名词）的检查。

## 9. 风险

| 风险 | 对策 |
| --- | --- |
| LLM 生成的规律无法执行，或者过于宽泛，导致全城死光 | 规律只能用行为原语；校验时用模拟跑一遍，估算每天的触发人数，超过阈值就拒绝 |
| 规律泄露进提示词，让角色「未卜先知」 | 提示词组装处统一过滤；单元测试检查提示词中不含 `rule` 的内容 |
| 世界被杀空 | 死亡预算；人员流动补充新居民；群众伤亡不影响具名角色 |
| 放开「杀」字后被滥用 | 硬禁区依然拦截血腥细节和现实伤害手段；dark 需要管理员显式授权；针对性事件只有所有者和管理员能发布 |
| LLM 调用成本上升 | 规律判定、战斗回合、负担值都不调用 LLM；只在开战、溃逃、派遣等节点调用，每场遭遇和每个事件都有调用上限 |
| 做成只有《夜巡》能用的能力 | §2 原则 1 和 §7.3 的通用性检查 |
| 和原著太像 | 避免清单；每只祟附带和原著的区别说明；三处原创设定 |
| 迁移影灵时改变了云溪镇的行为 | 迁移前后的回放必须逐项一致 |

## 10. 已确认的决策（2026-09-27 ~ 2026-09-28）

1. 新增 `dark` 分级，不复用 `tragic`。
2. 管理员按用户设置可用分级；`dark` 必须显式勾选。
3. 针对具体居民的袭击类事件，只有世界所有者和管理员可以发布。
4. 现有世界（云溪镇、小红帽）保持原分级，新能力按世界包字段启用。
5. 群众伤亡在 D1 只记数字，D6 再在地图上画出小人。
6. 死亡预算默认每 3 天最多 2 名具名角色，管理员可以按用户放宽。
7. 《神秘复苏》只作为题材参考，不复刻：原著的人物、地名、具体怪异、专有名词和剧情都不使用；示例世界的世界观和名词全部原创。
8. 内核只加通用能力；《夜巡》的专有名词只出现在世界包数据里。
