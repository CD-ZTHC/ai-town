# 冒险、成长与战斗观感 —— 设计方案

> 状态：实施中（2026-10-04，分支 `feat/adventure`）。
> 决策（2026-10-04 确认，见 §11）：
> 1. 玩家（旅人化身）**复用居民的能力，用同一套代码**，只在上面加限制（成长、回复、技能都一样，§3.9）。
> 2. 架构师可以新增普通战斗怪（`addMonster`）。
> 3. **区域不限数量**，改为「激活机制」：一段时间没人去的区域进入休眠，重新被访问时按流逝的时间推算出最新状态，推算不了的部分交给 AI 推演（§3.5）。
> 4. 战斗音乐跟随音效开关。
> 5. 暂时只支持一支远征队伍，但数据结构和接口按多支来设计（§3.4）。
> 相关：[combat.md](combat.md) 即时战斗与创世；[presentation.md](presentation.md) 演出与打击感；[ui-modes.md](ui-modes.md) 观察 / 沉浸 / 游戏三种模式；[night-watch.md](night-watch.md) 威胁、分级与死亡；[epic-outline.md](epic-outline.md) 史诗与大纲；[map-evolution.md](map-evolution.md) 区域与地图。

## 0. 一句话概括

给内核补上一组**通用、可选**的能力，让任何世界都能讲「冒险」：角色会**成长**；受伤后会**撤回回复点休整**，不会轻易倒下；可以**结伴同行**；沿着**远征前线**一个区域接一个区域往外推，地图也随之扩展。同时把这些过程**画出来**：观众打开页面 30 秒内，不用任何操作，就能看懂四件事——谁在打、打得怎么样、变强了多少、走到哪了。

验收用一个「勇者斗恶龙」式的原创世界包《破晓远征》（§8）。它只是 `worlds/` 下的一个世界包，**内核和前端里不出现任何它专有的名词**。每项能力都要在至少一个其他世界里有用处（§7）。

### 1.2 缺口

| 缺口 | 现状 | 影响 |
|---|---|---|
| **成长** | `computeStats` 只算人设、勇气和装备；没有经验和等级 | 看不出「变强」 |
| **生命上限** | `woundAgent / healAgent / bodyTick` 都把 hp 限制在 1~100；装备的 `mods.hp` 只在战斗单位里生效 | 成长没法体现在血量上 |
| **装备叠加** | `computeStats` 把身上所有装备的加成相加，不分槽位 | 带两把剑会叠加，掉装备换装备时很奇怪 |
| **回复点** | `sendToClinic`（`server/sim.ts:679`）只认 id 为 `clinic` 的地点、不分区域；22:00 以后不送；只排一小时日程，本身不回血 | 在远处的区域受伤后不知道该去哪；回血全靠自然恢复（醒着每天约 11 点） |
| **撤退** | 只有血量低于 30 被记为重伤，或在战斗中被打倒时，才会被送走 | 没有「血不多了，先撤」这个判断 |
| **结伴** | 没有「跟着谁走」的机制 | 队伍凑不到一起，很难打出群战配合 |
| **前线** | 讨伐（`hunt`）只出现在黑暗威胁的规划提示里（`server/sim/dark.ts:370`）；规划日程时没有「前线」这个概念 | 主角不会自己往外推 |
| **区域上限** | 世界最多 6 个区域（`server/kernel/ops.ts:518/557`、`server/worlds/review.ts:18`） | 推进到第 6 个区域就走不下去了 |
| **怪物形象** | 威胁只画成一个 emoji（`public/js/render/dark.js` 的 `drawThreat`）；异界生物只有 3 种体型（`wisp / hound / warden`） | 新区域的怪看起来没区别，Boss 没有体量感 |
| **角色动作** | 居民只有行走帧，出招靠位移和闪白模拟 | 看不出挥砍、施法、举盾 |
| **导演镜头** | 候选里没有「战斗」这一项，只能通过动态日志间接命中 | 挂机观看常常错过战斗 |
| **全局地图** | 只能看到当前区域 | 看不出推进 |
| **场景** | 没有洞窟、废墟、城堡这类地下或室内地貌 | 迷宫和最终决战缺场景 |

## 2. 原则

1. **内核只放通用能力**，名词只写进世界包。每项能力都要在至少两类世界里用得上（见 §7）。
2. **按字段启用**：世界包没有声明 `growth`、`recovery`、`expedition` 等字段时，相关逻辑完全不运行，存档和画面都不变。唯一的例外是 §3.2 回复点的通用化：旧世界的「送诊所」会变成「送去最近的回复点」，但有 `clinic` 的世界结果和现在一样。
3. **观众优先**：每项服务端能力都要配一个前端表现（§4）。不能只在数据里存在，画面上要看得出来。
4. **每一拍不调模型**：成长、回血、撤退、刷怪、解锁全部按规则结算。模型只在开场白、撤退字幕、篝火夜谈、区域引子这几个节点出场，并且都有兜底文本。
5. **AI 也能用**：架构师、创世流水线、剧情导演都能使用这些能力，各有边界（§3.8），用户自己创建的世界同样拥有全部能力。
6. **可重放**：所有随机数带种子，状态变化都有记录。

## 3. 系统能力（服务端）

### 3.1 成长：经验、等级、属性

**世界包**：

```json
"growth": {
  "who": "personas",
  "maxLevel": 40,
  "curve": { "base": 20, "mult": 1.3 },
  "tracks": {
    "fighter": { "perLevel": { "atk": 1, "def": 0.6, "maxHp": 14 }, "learn": [{ "level": 5, "ability": "heavy_slash" }] },
    "healer":  { "perLevel": { "atk": 0.4, "def": 0.4, "maxHp": 9 }, "learn": [{ "level": 3, "ability": "mend_light" }] }
  },
  "share": "participants"
}
```

- 字段含义：
  - `who`：哪些角色会成长。`personas` 表示人设里写了 `growth` 的角色，`all` 表示所有居民。
  - `curve`：升到下一级需要的经验为 `base × mult^(等级-1)`，取整。
  - `tracks`：成长路线，人设用 `growth: { "track": "fighter", "level": 1 }` 选择。
  - `learn`：到某个等级自动学会某项能力，复用 `grantAbility`。
  - `share`：经验怎么分。`participants` 表示战斗结束时，活着的我方参战者平分，最后一击另加 20%；`killer` 表示全给最后一击的人。
- **经验来源**：
  - 威胁新字段 `exp`（不写时按 `hp / 5` 估算）；
  - 新效果原语 `{"op":"exp","amount":1~500,"target":…}`，剧情、规则、任务奖励都能用；
  - 回复点里的「训练」等能力也能给。
- **结算**：
  - 写在居民身上：`a.growth = { level, exp, track }`；
  - 属性在 `computeStats` 里叠加：`atk / def` 加上 `perLevel × (等级 - 1)`，取整；
  - 升级时 `maxHp` 增加，同时补回增加的这部分血量。
- **表达式**：新增函数 `level(e)`；`agentView` 加入 `level / maxHp`。
- **事件**：`levelup {agent, level, gains, learned[]}`，写进动态（标记为 `milestone`）和记忆（重要度 6）。
- **AI 可见**：等级写进人设块（例如「你现在是 9 级的战士」），让对话里会出现「我比上个月强多了」之类的说法。

### 3.2 生命上限与回复点

**生命上限**：

- 居民的 `body` 新增 `maxHp`，默认 100，存档里没有时按 100 处理。
- 装备 `mods.hp` 和成长都加在 `maxHp` 上。
- `woundAgent / healAgent / bodyTick`、战斗单位适配器统一改用 `maxHp`。
- 「重伤」的判定从「低于 30 点」改为「低于 `maxHp` 的 30%」，「恢复到一半」同理。

**装备槽位**：

- `computeStats` 改为**每个 `equip` 槽位只取一件**，取加成最高的那件。同一槽位的其他装备留在背包里，检视面板标「未装备」。
- 原来叠加的效果在已有世界包里没有用到，这处改动不影响旧世界。

**回复点**：

```json
"recovery": {
  "kinds": ["clinic", "inn", "temple", "camp"],
  "rate": 1.5,
  "retreatAt": 0.35,
  "resumeAt": 0.9,
  "night": "stay",
  "downed": "carry"
}
```

- 回复点有两种认定方式：
  - 地点的 `kind` 在 `kinds` 里；
  - 地点显式声明 `rest: { "rate": 2, "text": "篝火边包扎" }`。显式声明的优先，可以覆盖速率和文案。
- **在回复点里**：每游戏分钟回复 `rate`% 的 `maxHp`，睡觉时翻倍。在那里工作的人（医生、神官）在场时速率 ×1.5，他们会记住「给谁治过伤」。
- **撤退**：
  - 居民不在战斗中，血量低于 `retreatAt × maxHp` 时，插入一段即时日程，去**当前区域里能走到的最近回复点**；
  - 区域里没有回复点时，去最近一个有回复点的相邻区域；还找不到就回家；家也太远就「就地包扎」，回血速率减半；
  - 血量回到 `resumeAt × maxHp` 后恢复原来的日程。
  - 战斗中的撤退沿用现有的逃跑判断（`wantsFlee`），脱战后再走撤退流程。
- **送医**：
  - `sendToClinic` 改名为 `sendToRest`，按上面的规则找地点；
  - 去掉 22:00 的限制，夜里按 `night: "stay"` 在回复点过夜。
- **被打倒（`downed`）**：
  - `carry`：有同伴（§3.3）或好感 ≥ 50 的人在 8 格内时，由他搀扶着走过去，两人同速移动；
  - 没有人可以搀扶时，过 30 游戏分钟后「被路过的人送到」回复点，直接移过去，并在那里醒来。
- **自动用药**：物品新增 `combatUse: true`。规则 AI 选招时把这类物品当作一个治疗招式打分，血量越低分越高。
- **事件**：`retreat {agent, to, reason}`、`rest {agent, at, healed}`、`downed {agent, by, carrier?}`、`revive {agent, at}`，前端用来做 §4.6 的表现。
- **兼容**：没有 `recovery` 字段的世界用默认值 `kinds: ["clinic"]`，`retreatAt` 为 0，即不主动撤退。行为和现在一样，只是去掉了 22:00 的限制、能找到别的区域里的诊所。

### 3.3 结伴同行

- 人设 `party: "队伍id"` 和世界包 `parties: { "队伍id": { "leader": "人设id", "name": "≤12字", "formation": "loose" } }`。
- 新效果原语 `{"op":"party","join":"队伍id"}` / `{"op":"party","leave":true}`，剧情和规则里用（例如「萤在古树妖倒下后加入」）。
- 行为：
  - **队员跟着队长的日程走**：同一地点、同一时段；没有去处时站在队长身后 1~2 格（`formation`），走路时排成一列。
  - **队长开打时，队员自动加入同一方**。战术按定位兜底：带治疗招的「护人」，`def` 高的「稳守」，其余「猛攻」。
  - 队长撤退，全队一起撤；队员撤退时，队长不会自动跟着撤。
  - 队员仍然有自己的思考、对话和记忆，只是日程被队长覆盖。队长每天规划日程时，提示里会写上队员的状态（血量、等级）。
- 快照新增 `parties`：前端用来画队伍卡片（§4.7）和走路队形。

### 3.4 远征前线

把「一个区域接一个区域往外推」变成数据，不再靠堆规则。

```json
"expedition": {
  "party": "队伍id",
  "stages": [
    {
      "id": "s1", "region": "区域id", "title": "≤12字", "intro": "≤60字（可空，空时由模型写）",
      "wild": ["地点id"],
      "spawns": [{ "threat": "威胁id", "every": 90, "max": 3, "when": "hour >= 7 && hour < 18" }],
      "boss": { "threat": "威胁id", "after": "kills >= 8", "foreshadow": 60 },
      "clear": "slain('威胁id')",
      "reward": [{ "op": "giveItem", "item": "物品id", "target": "e" }],
      "unlock": ["下一段的 stage id"]
    }
  ],
  "tokens": { "name": "≤6字", "emoji": "一个emoji", "total": 4 }
}
```

- **阶段**：每一段对应一个区域。阶段有四种状态：`locked`（未解锁）、`open`（已开放）、`front`（当前前线）、`cleared`（已征服）。`unlock` 可以有多个，用来做分岔路线。
- **刷怪**：
  - 只在 `wild` 里列出的地点或该区域的户外地点刷；
  - 只在队伍在场、队长血量高于 `resumeAt` 时刷；
  - 刷在队伍视野边缘 6~10 格处，不会直接贴脸；
  - 同时存在的数量不超过 `max`，消失的会补上；
  - 已征服的区域刷新频率降到 1/3，并且不再出 Boss。
- **Boss**：`after` 满足之后，按 `foreshadow`（分钟）提前发出预告事件（§3.7），时间一到就在 Boss 的 `haunt` 地点出现。
- **征服与解锁**：
  - `clear` 满足时，执行 `reward`，并对 `unlock` 列出的阶段调用 `openRegion`；
  - 发出 `frontier {from, to}` 事件（前端画道路点亮，§4.5）；
  - 写入设定集，并在史诗大纲里标记为当章事件。
- **规划**：
  - 队长规划日程时，提示里加一段「前线」：当前前线是哪里、还差什么（比如「再清掉 3 只」「Boss 还没出现」）、离最近的回复点多远；
  - 新增行动 `{"type":"hunt","region":"区域id"}`，表示去前线清剿，与威胁的 `hunt` 并存；
  - 没有模型时的兜底日程：早上出发去前线的野外地点，傍晚回到最近的回复点。
- **进度**：
  - 快照新增 `expedition`：各阶段状态、当前前线、击败数、`tokens` 收集进度；
  - 表达式新增 `kills('区域id'?)`、`stage('id')`（返回阶段状态）、`slain('威胁id')`。
- **为多支队伍预留**：
  - 世界包写 `expedition`（一支）或 `expeditions`（列表）都可以，内部统一成列表，每支有自己的 `id`（不写时为 `main`）；
  - 存档里的进度按 `id` 分开存（`adventure.expeditions[id]`），快照、事件都带 `id`；
  - 表达式函数接受可选的队伍 id 参数（`stage('s2', 'main')`）；
  - 校验时暂时限制为 1 支（`MAX_EXPEDITIONS = 1`），以后放开只需改这个常量和前端的面板。
- **野怪不开事件**：远征刷出来的怪是「野怪」，不像《夜巡》的威胁那样开启事件、划封锁区、写设定集。威胁新字段 `incident: false` 表示这种行为，`addMonster` 新增的怪默认就是它；被打倒时也不写设定集（Boss 除外）。

### 3.5 区域不限数量：激活与休眠

区域数量不再设上限（去掉 `ops.ts` 和世界包审核里的 6 个上限），靠「激活机制」控制开销。

**状态**：每个区域（主地图除外，主地图永远激活）有两种状态，记在存档字段 `regionState` 里：

| 状态 | 含义 | 模拟 |
|---|---|---|
| `active` 激活 | 最近有人来过 | 照常运行 |
| `dormant` 休眠 | 超过 `REGION_IDLE`（默认 6 游戏小时）没有任何居民、化身、战斗，也没有观众在看 | 区域里的威胁、生物、远征刷怪都不运行；前端不再随初始数据下发这张地图 |

「有人来过」包括：有居民、化身或战斗在区域里；有居民正走在去这个区域的路上；有观众在前端打开了这个区域（请求地图时激活）。

**唤醒时按流逝的时间推算最新状态**（`server/sim/dormancy.ts`，只依赖显式输入，可以单独测试）：

| 内容 | 推算方式 |
|---|---|
| 会死的威胁 | 按休眠时长回血（每小时回复 `maxHp` 的 10%）；走回常出没的地点；Boss 的阶段重置 |
| 活动时段 | 按唤醒时刻重新判断在不在活动时段 |
| 远征刷怪 | 已征服的区域：按 `every` 和休眠时长补齐到 `max`（只补到上限）；前线区域：不补，等队伍到了再刷 |
| 异界生物 | 回到各自常去的地点，敌意、躲藏状态按时刻重新判断 |
| 构筑物 | 本来就按全局时间过期，不需要处理 |

**推算不了的交给 AI 推演**：区域休眠超过 `REGION_AI_DAYS`（默认 2 游戏天），而且世界有模型时，唤醒后异步调用一次模型（标签「区域推演」）。

- 输入：区域的名字、地点、建筑状态、在那里的威胁、相关的设定集与最近的动态、休眠了多久。
- 输出（严格校验，不合法的条目直接丢弃）：
  - 一句话概括这段时间发生了什么，写进动态和设定集；
  - 最多 3 条变化，只能是白名单里的世界操作（`setBuildingState`、`restoreBuilding`、`plantGrove`、`addOutdoorPlace`、`addCanon`），以及让世界包里已有的威胁在某个地点出现（只能是会死的、普通的怪，不能是 Boss）。
- 模型的结果到达之前，区域已经按推算的状态运行；结果到达后再应用。
- 没有模型或出错时，只用推算的结果，并写一条兜底动态（「（区域名）安静了很久」）。
- 同一个区域两次推演至少间隔 1 游戏天；每个世界每游戏天最多推演 4 次。

**前端按需加载**：
- 初始数据只带激活区域的完整地图，休眠区域只给名字和尺寸；
- 切换到休眠区域时，前端先请求 `GET /api/region?id=`，服务端唤醒它再返回地图；
- 收到区域被唤醒或休眠的事件后，前端更新状态。

**内存**：区域地图本身常驻服务端（寻路、路口都要用），休眠省下的是每分钟的模拟开销和前端的下载量。上线前要测一测 20 个区域时的内存占用。

第二部（`sequel`）可以把上一部的区域保留为「已征服」，用 `worldOp` + `generate` 继续往外长出新区域。

### 3.6 掉落、里程碑与战斗事件

- 威胁被打死时的事件 `slain` 带上 `{by, exp, drops[]}`。`server/story/threats.ts:510` 目前只是悄悄把掉落放进背包，前端无从得知。
- 招式读条开始时的范围预警已经有了（`combat` 事件的 `casts` 带 `from / aim / shape / range / radius / ms`，见 realtime.md §5.3），本方案只调整前端画法（§4.3）。
- 动态新增 `milestone` 标记，用于升级、击败 Boss、解锁区域、第一次到达某地、险些倒下（hp < 10%）、加入队伍。冒险日志（§4.7）只列这些。

### 3.7 预告

- 威胁新字段 `foreshadow: { "lead": 30~240, "text": "≤40字", "sound": "声音id(可选)" }`。无论是远征 Boss 还是规则里的定时 `spawnThreat`，都可以提前发预告。
- 事件 `foreshadow {threat, region, eta, text}`，`text` 为空时由模型写一句，并有兜底文本。
- 居民在附近时会听到、写进记忆，可以变成谈资（复用 `spreadNews`）。
- 《夜巡》的规律型威胁已有的征兆（`mark.sign`）不变，两者可以并存。

### 3.8 AI 能用到哪一步

| 谁 | 能做什么 | 不能做什么 |
|---|---|---|
| 剧情导演 | 发出预告、在前线安排一波伏击（复用 `spawns` 里写好的威胁）、让人入队 / 离队 | 改成长曲线、凭空造 Boss |
| 世界架构师 | 新增**普通战斗怪**（新操作 `addMonster`：只能是 `mortal`、没有 `rule`、属性有上限的威胁，minor 审批）；为新区域补充远征阶段（`addStage`，major 审批）；新增回复点（`addBuilding` 的 `kind` 填回复点类型即可） | 写 `onSlain` 里的 `worldOp`、改 `growth` |
| 创世流水线 | 用户以战斗为基调创建世界时，生成 `growth / recovery / parties / expedition` 和怪物的 `look`（作为单独一步，像大纲那样） | —— |
| 世界包 | 全部 | —— |

### 3.9 旅人化身复用居民的能力

玩家操控的旅人化身和居民用**同一套代码**：成长、回复点、战斗属性、学招都调用同一组函数（`server/sim/growth.ts`、`server/sim/recovery.ts`），化身只是在上面多了几条限制。

| 能力 | 居民 | 化身的限制 |
|---|---|---|
| 成长 | `growth.tracks` 里的路线 | 用世界包的 `growth.avatar.track`（不写时取第一条路线）；等级上限为 `growth.avatar.maxLevel`（不写时为居民最高等级 + 2，至少 5），不会把居民远远甩在后面 |
| 经验 | 战斗结束时按 `share` 分 | 同样按 `share` 分；化身对居民动手不给经验 |
| 学招 | `learn` 里的能力直接学会 | 只能学带 `combat` 块、非创世级的能力，学会后加进自己的技能栏（技能栏最多 4 个，满了时替换最早学的那个，世界的 `avatarKit` 保留） |
| 生命上限 | `maxHp` | 同一个计算函数 |
| 回复 | 回复点 | 被打倒后在最近的回复点醒来（以前是回到出生点）；在回复点里回血速度和居民一样，离开回复点、脱离战斗时仍保留现有的快速回血 |
| 存档 | 写在居民身上 | 化身本身不进存档，但等级和经验按「账号 + 世界」存在存档字段 `adventure.avatars[uid]` 里，下次现身时接着用 |

## 4. 表现能力（前端）

本节只依赖快照和事件，不关心是哪个世界。世界包可以用 `look`、`ambience` 这类字段定制外观，不写时都有默认值。

### 4.1 怪物外观系统

- 威胁和异界生物统一使用 `look`：

  ```json
  "look": { "bodyPlan": "beast", "scale": 1.5, "palette": { "body": "#5b7a3a", "accent": "#c9e36b", "eyes": "#ff5a3a", "glow": "#d4ff7a" }, "pattern": "spots", "aura": "none" }
  ```

- **体型库**：在 `public/js/sprites.js` 里扩充参数化画法，现有的 `wisp / hound / warden` 保留。

  | 体型 | 适合 |
  |---|---|
  | `blob` | 史莱姆、软泥 |
  | `beast` | 狼、熊、野猪 |
  | `bird` | 蝙蝠、鸦、鹰身 |
  | `insect` | 甲虫、蝎、蜘蛛 |
  | `humanoid` | 山贼、哥布林、骑士 |
  | `treant` | 树精、藤蔓 |
  | `golem` | 石像、熔岩巨像 |
  | `skeleton` | 骸骨、亡灵 |
  | `serpent` | 蛇、蠕虫 |
  | `eye` | 浮游眼、魔像核心 |

- 其他参数：
  - `pattern`：`plain / spots / stripes / crystal / bone / ember`；
  - `aura`：`none / smoke / fire / frost / shadow / holy`，用粒子画出来；
  - `scale`：1~3。Boss 默认 2，带脚下阴影、呼吸起伏，周围压暗。
- **绘制**：每种外观生成一次离屏画布并缓存；行走 3 帧，攻击和受击各 1 帧。
- **校验**：`look` 字段走白名单，颜色只接受 `#rrggbb`，架构师 AI 也能写。没写 `look` 的威胁继续用 emoji，旧世界不变。
- **击败**：像素粒子向外溅开后消散；Boss 先定格，再碎裂发光。

### 4.2 角色姿势与武器图层

- 人形精灵（居民和旅人化身）新增 4 个姿势帧：挥砍、施法、举盾、倒地。按招式自动选择：
  - `shape` 为 `line / cone / single` 且有 `strike`：挥砍；
  - `shape` 为 `circle`，或招式里有 `heal / status`：施法；
  - 招式里有 `shield / guard` 状态：举盾。
- 物品新增 `look: { "weapon": "sword/axe/staff/bow/spear/dagger/shield", "color": "#rrggbb", "glow": "#rrggbb" }`。装备后精灵多画一层武器（行走时随手摆动），出招时跟着姿势动。
- 换装备时武器图层立即改变，这是「变强」最直观的画面。

### 4.3 战斗可读性

- **阵营描边**：观众关注的一方（§4.7 的焦点角色及其队伍）用蓝色细描边，敌人用红色，第三方用灰色。
- **目标线**：蓄力中的单位到目标之间画一条半透明细线。
- **范围预警**：读条开始时，按 `shape / range / radius / dir` 在地面画红色范围，随读条逐渐填满。蓄力 ≥ 3 拍的大招才画，避免满屏红圈。
- **连击与暴击**：同一人 2 秒内连续命中时显示连击数；暴击时字更大，命中瞬间停顿加长到 120ms。
- **掉落**：物品图标从倒下的位置弹起，沿弧线飞向拾取者，飘出「+名字」。
- **经验**：战斗结束时，各参战者头顶飘一行金色小字「+18」。

### 4.4 成长可视化

- **升级演出**：金色光柱从脚下升起，粒子上扬，播放上行音阶，名字卡显示「名字 · Lv N」，下方弹出属性对比小卡（攻 12→14、血 140→155），3 秒后淡出。属于 `minor` 演出，焦点角色升级时升为 `major`。
- **习得新招**：横幅「习得：招式名」；第一次使用这招时，自动加一段 0.5 秒的慢镜。
- **等级徽章**：有成长的角色在名牌旁显示「Lv N」，战斗中显示在血条左侧。
- **检视面板**：新增「成长」页，包括经验条、等级曲线（每一级是哪天升的）、学会的招式、装备栏（各槽位当前的装备）。

### 4.5 世界全图与区域标题卡

适用于所有多区域的世界，包括云溪镇加暗月界、《开天》的天穹与大地。

- **全图**：
  - 右上角放小地图，点开后是全屏世界全图，羊皮纸风格；
  - 区域位置：相邻区域按 `adjacent.side` 自动拼接，用传送门相连的区域可以写 `atlas: {x, y}`，不写时自动排在连接点附近；
  - 区域状态：

    | 状态 | 画法 |
    |---|---|
    | 未知 | 迷雾，只露出轮廓和「？？？」 |
    | 已开放 | 黑白缩略图 |
    | 当前前线 | 彩色并闪动边框 |
    | 已征服 | 彩色并插旗 |

  - 焦点角色用头像标出当前位置，走过的路线用虚线画出（前端记录，存在浏览器里）。
- **道路点亮**：收到 `frontier` 事件时，镜头拉远到全图，一道金线从原区域延伸到新区域，迷雾散开、名字浮现，然后切回现场。作为 `reveal` 模板的变体，属于重大演出。
- **区域标题卡**：焦点角色第一次进入某个区域时，全屏淡入「{阶段标题} · {区域名}」和一句引子（`intro`，或者模型写的），2.5 秒。没有远征的世界只显示区域名，同一个区域只播一次。

### 4.6 危险、撤退与休整

- **危险提示**：焦点角色血量低于 30% 时，屏幕边缘出现红色暗角和低沉的心跳音，血条闪烁；脱离危险后淡出。
- **撤退字幕**：收到 `retreat` 事件时，底部显示一行字幕，例如「{name}咬牙退出战场，往{地点}撤去」。字幕由模板生成，模型写好的版本到了就替换。导演镜头跟着撤退的人走一段。
- **回复点**：所有回复点都有柔和的光圈（复用夜间光照）；`camp` 类型加篝火粒子。在回复点回血时，绿色粒子持续上升，飘出「+」数字（合并成每 2 秒一次）。
- **被打倒**：画面短暂变灰、慢镜，角色倒地。
  - 有人搀扶：两人一起慢慢走向回复点，镜头跟着；
  - 没有人搀扶：黑屏一秒，然后在回复点醒来，在那里工作的人说一句话（模型写，有兜底文本）。
- **篝火夜谈**：傍晚以后，同一回复点里有两位及以上队员在对话时，成为导演镜头的高分候选。画面上暖光、压暗四周，字幕显示对话。

### 4.7 观察界面：焦点角色与冒险者面板

- **焦点角色**：世界包 `spotlight: ["人设id"]`。不写时取有远征的队伍的队长，没有远征的取 `lead` 角色。观众可以在检视面板里「设为焦点」，记在浏览器里。危险提示、标题卡、全图头像都跟着焦点角色。
- **冒险者面板**：观察模式左侧常驻（可以收起）。

  ```
  ┌──────────────────────────────────────────────────────────────┐
  │ 第 12 天 07:40 ☀                    📍 区域名（前线）   [🗺] │
  │ ┌─────────────┐                                              │
  │ │😠 队长 Lv 9 │                                              │
  │ │████████░ 132│           （地图 / 战斗现场）                  │
  │ │🙏 队员 Lv 8 │                                              │
  │ │█████░░░░  88│        ┌──────── Boss 名 ────────┐           │
  │ │🛡 队员 Lv 8 │        │██████████░░░░░ 第二阶段 │           │
  │ └─────────────┘        └─────────────────────────┘           │
  │ 今日：击败 14 · 拾取 6 · 撤退 1          进度 ◆◆◇◇           │
  │ 「预告 / 旁白字幕」                                           │
  └──────────────────────────────────────────────────────────────┘
  ```

  - 每张队员卡片包括头像、等级、血条，以及当前状态（战斗中 ⚔ / 撤退中 ↩ / 休整中 🏕 / 行军中 🚶）。点击卡片，镜头跟过去。
  - 底部一栏：今日战绩（击败、拾取、撤退）和远征进度（`tokens`）。
  - 预告事件以一条滚动提示出现在顶部，例如「（区域名）深处的低语越来越响……」。
- **冒险日志**：侧栏新增「冒险」页，按时间线只列 `milestone`，每条可以点击跳到当时的位置（复用回溯）。
- **三种模式分层**：

  | 元素 | 观察 | 沉浸 | 游戏 |
  |---|---|---|---|
  | 队伍卡片 | 完整 | 缩成左下角头像 | 隐藏（技能栏优先） |
  | Boss 血条 | ✅ | ✅ | ✅ |
  | 小地图 | ✅ | 隐藏 | ✅ |
  | 危险暗角 | 焦点角色 | 焦点角色 | 自己的化身 |
  | 标题卡、升级演出 | ✅ | ✅ | 只播字幕 |

### 4.8 导演镜头适配战斗

在 `public/js/immerse.js` 的候选里新增以下几项：

| 候选 | 分数 |
|---|---|
| 进行中的战斗 | 85 + 参战人数 × 5，有焦点角色时 +25 |
| Boss 战 | 120，期间锁定，不切走 |
| 焦点角色撤退或被打倒 | 95 |
| 升级、掉落、道路点亮 | 抢占（作为演出播放） |
| 篝火夜谈 | 75 |
| 焦点队伍行军（在野外移动） | 40 |
| 风景空镜 | 不变；连续战斗超过 2 分钟后，插一个 5 秒的空镜喘口气 |

- **取景**：战斗用参战单位的包围盒自动缩放，最多推近到 2.2 倍；Boss 战用固定的宽景，让 Boss 体量看得出来。
- **关键时刻**：焦点角色血量第一次跌破 15%、Boss 换阶段、最后一击时，自动加 0.4 秒慢镜并推近。这些都用现有的分镜步骤，前端自动触发，不占服务端的演出名额。

### 4.9 地貌、氛围与音乐

- **新地貌**（加进 `BIOMES`，并补上对应的物件画法）：

  | 地貌 | 画法 |
  |---|---|
  | `cave` 洞窟 | 暗色岩地、钟乳石、水洼；整张地图压暗，只有角色和火把周围亮 |
  | `ruins` 废墟 | 沙色地面、断墙、半埋的石柱 |
  | `castle` 城堡 | 石砖地面、红毯、火盆，墙体成片 |
  | `volcano` 火山 | 黑岩、熔岩缝（发光），飘余烬 |

- **氛围**：地貌和区域都可以带 `ambience: { "tint": "#rrggbb", "tintAlpha": 0~0.4, "particles": "motes/leaves/embers/sand/snow/fog/none", "sound": "wind/birds/cave/fire/hum/none" }`，不写时由地貌决定默认值。在 `public/js/render/atmosphere.js` 和 `public/js/sfx.js` 现有的环境层上扩展。
- **战斗音乐**：开打时淡入一段程序生成的鼓点和低音，Boss 战换成更快的节奏，战斗结束 2 秒后淡出。设置里可以关闭，默认跟随「音效」开关。

### 4.10 性能与移动端

- 怪物精灵按外观缓存；全世界粒子总数设上限（例如 400），超出时先丢弃远处的粒子。
- 回复点的绿色数字、经验飘字按 2 秒合并一次。
- 手机上：冒险者面板默认收起，只显示焦点角色的头像和血条；全图改为全屏弹层。

## 6. 存档与兼容

- `body.maxHp`、`growth`、`party` 都是新增字段，读档时没有就按默认值处理。
- `expedition` 的进度存在世界状态里（`expeditionState`）。世界包后来新增的阶段，读档时按 `locked` 补上。
- `computeStats` 的装备槽位改动、`sendToClinic` 的通用化会改变旧世界的结果。改之前先确认现有世界包里没有同槽多件装备的情况，再在 `test/` 里加上旧世界的回归用例。
- 冻结区里的文件（`core.lock` 记录的）改动后要重新生成哈希。

## 10. 风险

| 风险 | 对策 |
|---|---|
| 画面信息太多 | 三种模式分层（§4.7）；演出设置（全部 / 仅重大 / 关闭）沿用；预警只画大招 |
| 镜头来回切 | 沿用最短停留与冷却；Boss 战锁定；连续战斗后插空镜 |
| 刷怪太多压垮主循环 | 每阶段 `max` 上限、`MAX_FIGHTS` 不变、只在队伍在场时刷、区域休眠 |
| 区域不限数量后开销上涨 | 休眠区域不模拟、前端按需加载；上线前实测 20 个区域的内存 |
| AI 推演写坏世界 | 只开放白名单里的少数操作、最多 3 条、严格校验；每区每天最多 1 次、每世界每天最多 4 次 |
| 成长让战斗失衡（主角太强，怪一刀死） | 远征阶段可以写 `levelHint`（建议等级），刷出来的怪按「阶段建议等级」缩放属性；越级的队伍刷怪变少，经验递减 |
| 旧世界行为改变 | 只有回复点通用化和装备槽位会影响旧世界，都有回归测试 |
| 模型写的字幕变慢 | 都是先发模板文本，模型的版本到了再替换（同演出的旁白） |

## 11. 决策（2026-10-04 确认）

1. **旅人化身复用居民的能力**，同一套代码，只加限制（§3.9）。
2. **架构师可以新增战斗怪（`addMonster`）**：只能是 `mortal`、没有规律、属性有上限的野怪，minor 审批。
3. **区域不限数量**，用激活与休眠控制开销；唤醒时按时间推算，推算不了的交给 AI 推演（§3.5）。
4. **战斗音乐跟随音效开关**。
5. **暂时只支持一支远征队伍**，数据结构和接口按多支设计（§3.4），以后放开只需改常量和面板。

## 14. 线上修复：点森林里的人后画面卡死（2026-10-04）

现象：线上点击幽影森林里的居民后，地图卡住、点其他居民也定位不过去、小地图变成空白。

原因：主循环在一帧开头按「当前地图」筛出要画的人，随后跟随镜头发现要跟的人在别的地图上，就在**同一帧里**把视图和渲染器换成了那张地图；这一帧接着用旧地图上的人去画新地图。小地图画「在屋里的人」时，到新地图的建筑里找不到那栋屋子（例如旅店），抛出异常；主循环没有防护，异常之后不再排下一帧，画面就永久停住。村里有人在屋里（傍晚、夜里）时必现，所以本地白天的场景没测出来。这个隐患在多区域的世界里一直存在，冒险让跨区域跟随变得常见才暴露出来。

处理（`public/js/main.js`、`public/js/render/overlays.js`）：
- 视图在一帧中途变了就跳过这一帧，下一帧按新地图重新筛人；
- 主循环加防护：任何一帧出错都只跳过这一帧（同一个错误只记一次日志），不会再让画面停住；
- 小地图与跟随镜头里查找建筑时，找不到就跳过。
