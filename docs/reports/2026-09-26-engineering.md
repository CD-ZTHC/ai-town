## 二、做了什么

### 1. 无头回放测试（设计文档 11.5 节）

`test/replay.test.js` 用录制的模型回复、固定的随机种子，以 30 倍速跑 **7 个游戏日**，完整走完一季《镜湖裂隙》。整个测试不到 0.5 秒。

检查的不变量：

- 每一步都检查：坐标有限且不越界；没有人连续走路超过 3 小时，或连续聊天超过 2 小时（卡住）。
- 每天中午：所有居民都有当天的日程。
- 上限：构筑物 ≤ 30，生物 ≤ 24，日志 ≤ 400，对话记录 ≤ 120，每人记忆 ≤ 400。
- 8 位原住民一个都没有被移除；每天至少一期日报（第 7 天高潮还会多一期号外）。
- 录制回复确实被用上了：规划、对话、独白、日记、日报、导演都被调用过，并留下了对应的日志。
- **所有世界操作都写进了 `ops.jsonl`**，而且从默认规格重放后，得到的世界规格与运行中的完全一致。
- 存档往返：时间、世界规格、居民、每个人的记忆条数都能恢复。

**这个测试真的能抓到问题**：我故意注入了两个 bug，它都报出来了。

| 注入的 bug | 报错 |
| --- | --- |
| 从第 3 天起林晓雨停在半路 | 「林晓雨 走了 183 分钟还没到」 |
| `addBuilding` 不写审计日志 | 「操作 #1 addBuilding 没有写进审计日志」 |

用 12 个不同的随机种子各跑一遍，全部通过，没有偶发失败。出错时可以用 `REPLAY_SEED=…` 复现。

**录制回复**放在 `test/fixtures/llm/responses.json`，按模块分组，同一模块的多条回复轮流使用。`smoke-llm.js --mock` 原来有一份内联的假回复，现在也改用这份，两边不会各写各的。

需要更新录制回复时，用真实模型跑一段：

```bash
LLM_RECORD=test/fixtures/llm/responses.json mise run start
```

每个模块保留最近 4 条；能解析成 JSON 的会存成对象，方便人工审阅和修改。

### 2. CI

`.github/workflows/ci.yml` 会在推送到 main 和提 PR 时运行，Node 22 和 26 各跑一遍，依次是：语法检查 → 全部测试 → `smoke-llm.js --mock`。

- 22 是 `package.json` 声明支持的最低版本，26 是 `mise.toml` 里用的版本。
- 语法检查改由 `tools/check.js` 递归扫描目录。原来 `mise run check` 把目录列表写死了，**新加的 `server/sim/` 会被漏掉**。
- `package.json` 新增 `npm run check`。

### 3. 拆分 `sim.js`

`sim.js` 只保留世界状态、主循环、天气、角色登场与离开、世界操作。其余方法原样搬到 `server/sim/`：

| 模块 | 内容 |
| --- | --- |
| `regions.js` | 地点查找、区域开关（暗月界）、地点列表 |
| `movement.js` | 当前该做什么、寻路、行走、到达、体力与勇气 |
| `planning.js` | 每日规划、兜底日程、约定、收到消息后重新规划 |
| `actions.js` | 使用能力、送东西、传授、研究 |
| `cognition.js` | 提示词片段、内心独白、反思、日记、日报 |
| `social.js` | 居民对话、信念传播、旅人聊天与心声、小镇事件 |
| `views.js` | 推送给前端的快照与各面板的视图 |
| `persistence.js` | 保存、每小时快照、读档与迁移、时光回溯 |

**做法**：每个模块是一个普通的 class，方法原封不动；`sim.js` 末尾把这些方法挂到 `Town.prototype` 上，方法里的 `this` 仍然是 Town。挂载时如果发现重名，启动就会报错，不会悄悄覆盖。

**为什么不改成「组合」**（`town.planning.planDay()` 这种）：那样要改动所有调用方，包括 `story/`、`worldai/`、`kernel/` 和测试里的几百处 `town.xxx()`，风险和工作量都大得多。mixin 能先把文件拆开，以后如果需要，可以按模块逐个再改成组合。

**验证**：

- 拆分由脚本完成，没有手工重写任何方法体。
- 拆分前后 `Town.prototype` 的成员集合相同，每个方法的源码逐字相同。
- 导出的 `Town`、`listSnapshots`、`restoreSnapshot`、`llmPublic` 不变。
- 服务器能正常启动，`/`、`/api/story`、`/api/usage`、`/api/proposals`、`/api/agent/lin` 都正常返回。

### 4. LLM provider 接口

新增 `server/llm-providers.js`。一个 provider 只需要提供 `enabled`、可选的 `listModels()` 和 `complete()`。默认的 OpenAI 兼容实现是从 `llm.js` 原样搬出来的，**仍然零依赖**。

`llm.js` 继续负责：并发队列、自适应限流、重试、JSON 模式自动降级、模型名纠正、每日预算、按模块统计、模拟模型、回复录制。

扩展方式：

- `LLM_PROVIDER` 环境变量选择用哪个 provider。
- `registerProvider(name, factory)` 注册新的实现。
- `llm.setProvider()` 给测试用，或者在启动时换成别的实现。

**以后要接 `pi-ai`**，只需要写一个把 `complete()` 转到 `pi-ai` 的适配器，并把它设为可选依赖，默认路径不受影响。

新增的 `test/llm-provider.test.js` 第一次覆盖了这条请求管线：

- 网关不支持 JSON 模式时，自动关闭并重试，之后的请求也不再带
- 鉴权失败不重试
- 空回复会重试
- 按模块统计用量
- 并发不超过 4 个
- OpenAI 请求体的格式，以及非 JSON 错误页的解析

### 5. 顺手修的三个小问题

- **每日额度按本地日期重置**：原来用 UTC 日期，在国内是早上 8 点才重置；现在按服务器所在时区的午夜。
- **前端转义**：天气菜单里的天气名和图标、命令面板里的地点图标，都可能由 AI 新增，现在转义后再插入 HTML。原来的风险很低（天气名最多 8 个字，而且 CSP 禁止内联脚本），这次顺手统一了。
- **记忆检索缓存双字组**：用 WeakMap 缓存每条记忆的双字组，不进存档；记忆被淘汰后自动回收，文本变了会重新计算。新增 `test/memory.test.js`，并确认缓存失效出错时这个测试会报错。

## 四、需要注意

- **旧存档里当天的令牌用量**：存档里原来记的是 UTC 日期，升级当天如果和本地日期不一致，重启后当天的用量不会恢复（只影响升级当天）。
- **`mise.toml` 里本地新增的 `claude-code` 工具**没有提交：这次只提交了 `check` 任务那一行。要不要提交由你决定；它会影响所有协作者的 `mise install`，也可以挪到 `mise.local.toml`。
- **录制回复目前是手写的**，格式参照了各模块的解析代码和原来 smoke 里的假回复。建议有空时用 `LLM_RECORD` 从真实模型录一份，让回放更接近真实输出。
- **CI 还没有在 GitHub 上实际跑过**（分支没有推送）；本地已经用 Node 22 和 26 跑通了同样的命令。

## 五、下一步建议

1. **存储**：存档跑两天就到了约 190KB，每小时快照都是完整副本。建议改用 Node 内置的 `node:sqlite` 增量存储，仍然零依赖；或者至少把快照用 zlib 压缩、改成异步写入。
2. **记忆压缩**：记忆超过容量时，不再直接删除，而是把旧的琐碎记忆压缩成「某天摘要」。可以加一个可选的 embedding provider，没配置时回落到双字组。
3. **前端拆分**：`render.js`（1717 行）和 `ui.js`（1035 行）可以沿用这次的办法拆开；拆之前最好先加一些 DOM 无关的纯函数测试。
4. **结构化输出**：对支持 `json_schema` 的网关，在 OpenAI 兼容 provider 里加一个开关，降低架构师输出复杂补丁时的失败率。
5. **AI 表现指标**：在回放测试和 `/api/usage` 的基础上，统计对话重复率、约定兑现率、剧情线程回收率、JSON 失败率。换模型时可以拿来对比。
