## 一、结论

P4 已完成，验收标准达到了：AI 新增的建筑能正确渲染、可以走进去、居民会使用；回溯后世界正确恢复。

| 验收项 | 结果 |
| --- | --- |
| 新建筑能渲染 | ✅ 浏览器实测：工地 🚧 → 完工的「观星塔」（自定义屋顶和墙色、🔭 招牌、夜灯），周围的树被清理，开出了连到道路的小路 |
| 可以走进去 | ✅ 门口可达性在选址时校验；测试里王小乐按日程走进了新建筑 |
| 居民会使用 | ✅ 新建筑自动成为公共地点，出现在居民规划用的地点列表里 |
| 回溯正确 | ✅ 测试：回溯后时间和世界结构（新增的天气）都回到快照时刻；接口实测备份与恢复 |

同前几个阶段一样，**架构师和考据官只用模拟模型验证过**，还没有接真实的 glm 模型。

## 二、做了什么

| 模块 | 作用 |
| --- | --- |
| 地图叠加 `world.js` | 新增的建筑（`added: true`）在原地图生成完之后叠加：清理占地及周围一格的树木、灌木和石头，开辟连到道路的小路，可选配一盏夜灯。**原地图其余部分逐格不变**（测试已断言）。 |
| 语义化选址 `kernel/placement.js` | AI 只描述「靠近哪个地点、多大」，求解器在附近找位置。硬性条件：占地是空地、与其他建筑隔一格、门口可达、原有建筑入口仍然可达、各地点的可达站位一个都不少。单次选址约 10~20 毫秒。 |
| 新 WorldOp `addBuilding` | 坐标由求解器写进操作参数，重放是确定的；落地后地图实时重建并推送前端。最多新增 12 座建筑。 |
| 提案 `worldai/proposals.js` | 流程：校验（含自动选址）→ 设定考据 → 审批 → 施工 → 落地。另外有每日配额，以及原位置被占用时重新选址。 |
| 世界架构师 `worldai/architect.js` | 用强模型把意图变成 1~4 个操作的补丁。提示词里带着自动生成的能力清单（可用操作、效果、表达式、现有地点 / 物品 / 能力）。补丁校验失败时带着错误修正一轮；做不到的事输出 `gap`，相似的缺口合并计数，进入「AI 心愿单」（P5 使用）。 |
| 设定考据官 `worldai/canon.js` | 规则检查（重名、违背「温馨、没有人会死亡」的支柱设定）+ 模型审查（检索相关设定条目，判断是否矛盾）。明显矛盾（major）直接驳回，小瑕疵只作为提示展示。模型调用失败时不阻塞，交给人把关。 |
| 意图的四个来源 | 叙事导演的新节拍 `propose`（每天最多 3 个）、居民聊天中聊出的点子（新字段 `idea`，每天最多 1 个）、访客建议（审核 + 每 IP 每小时 2 条 + 每天最多 4 个）、管理员（不限）。 |
| 时光回溯 | 每个游戏小时的快照（保留 24 份）可以一键恢复：先校验快照，再保存并备份当前存档，然后用快照重建小镇。 |

### 审批规则（按你的决定实现）

| | 微调（如写一条设定） | 小改（新建筑、节日、天气、物品、能力） | 大改（新世界法则、调参数） |
| --- | --- | --- | --- |
| 本地模式 | 自动通过 | 自动通过 | 等管理员确认 |
| 公网模式（设置了管理员令牌） | 自动通过 | 访客投票 1 小时 → 管理员终审 | 同左 |

- 公网模式下，**24 小时内无人终审的提案会作废，不会自动通过**。这和剧情抉择不同：剧情抉择会按多数决定，为了让无人值守时剧情能继续；世界改动更需要人把关。
- 每个游戏日最多落地 3 个小改、1 个大改，超出的会排到第二天。
- 新建筑都要施工：先出现工地，默认由赵铁柱施工 4 小时，也可以指定施工的人和时长。

### 前端「🛠 建设」面板

- **🛠 提案**：提建议的输入框；每份提案显示状态、级别、来源、动机、改动列表，新建筑还会在小地图上标出位置；有考据官意见、赞成 / 反对投票，管理员可以批准 / 驳回。
- **📜 编年史**：所有世界变更，以及它们的来源。
- **🧩 AI 心愿单**（管理员）：架构师做不到的事，按出现次数排序。
- **⏳ 时光回溯**（管理员）：快照列表，一键回到某个时刻。

## 三、验证情况

- **测试：共 65 个，全部通过**（约 2 秒）。本阶段新增 12 个，覆盖：
  - 地图叠加不改变原地图、选址的各种拒绝情况
  - 新建筑可以走进去，读档后仍在
  - 本地模式下的施工全流程、大改确认 / 驳回、每日配额排队
  - 公网模式下的投票 → 终审 → 作废
  - 考据官：规则检查与模拟模型审查
  - 架构师（模拟模型）：修正一轮、能力缺口合并
  - 点子来源的每日上限、导演的 `propose` 节拍
  - 时光回溯
- **浏览器实测**：管理员提交「码头观星塔」补丁 → 开工（铁柱、大山去码头）→ 工地 → 完工落地 → 建设面板、编年史、回溯页都正常，页面没有脚本错误。

### 开发中发现并修复的问题

| 问题 | 修复 |
| --- | --- |
| 回溯接口在校验快照名之前就停止了小镇：快照不存在时会从磁盘重新加载，丢掉最近最多 20 秒的进度；回溯前也没有先存盘 | 改为先校验、再存盘备份、最后停止 |
| 施工完成时总是重新选址，建筑可能落在和预览、工地不同的位置 | 先按原坐标落地，原位置被占用时才重新选址 |

## 四、已知限制

- **不能拆除或移动建筑**，也不能改地形（湖、路、田）。这类需求会进入 AI 心愿单。
- **施工的人去的是附近的地点**（例如码头），不是工地本身，因为工地在完工前还不是一个地点。
- **回溯的粒度是整点快照**，没有做「撤销某一条世界变更」：单独撤销一条可能让依赖它的角色、剧情状态失去一致性。
- **中央广场、农场周围几乎没有空地**：广场被道路和铺装围着，农场被田地和篱笆围着，默认 12 格内选不到位置。架构师可以把范围放宽到 16 格，或者换一个地点。
- **AI 生成新的异界生物还没开放**：图鉴数据已经支持，但生物只能由剧情弧召唤，暂时没有让架构师新增生物种类的操作。

## 五、建议的下一步

   - 居民聊出来的点子是否自然

   - 考据官是否过严
