# 汇报：自主迭代、自主演化（E0–E5）

> 日期：2026-09-26 · 分支 `claude/lucid-lamport-ye9rtq`
> 设计方案：[docs/design/autonomous-evolution.md](../design/autonomous-evolution.md)（§15 记录了实施与设计的出入）

## 一句话

小镇现在可以在无人值守的情况下自己长出新功能：进化引擎从 AI 心愿单里挑需求，写需求文档 → 需求评审 → 实施 → 自动闸门 → 三位审查员多轮评审 → 安全终审 → 影子试运行，做成插件交给大家表决；管理员在终审窗口内没有处理的事，由 AI 裁决官在代码执行的硬规则之内决定；上线先灰度，出错自动回滚。所有新功能都在独立的插件目录里，内核冻结。用真实模型（glm-5.3 / glm-5.3-flash）完整跑通了一个数据插件和一个代码插件。

## 已确认的决策如何落地

| 决策 | 实现 |
| --- | --- |
| AI 先写需求文档，Agent 评审后实施 | 流水线第一步是需求文档撰写，第二步是**需求评审 Agent**（可以退回修改、降级、否决、转为 T3）；通过后才进入实施 |
| AI 生成的代码要多轮 Agent 评审 | 安全 / 正确性 / 世界观三位审查员并行、互不可见；有阻断问题退回修复、由提出问题的审查员复审（最多 3 轮）；最后由全新上下文的安全终审放行（代码插件两次：攻击者视角、运维视角，只看去掉注释的代码）；终审通过后锁定内容哈希 |
| 公网可以上线，由配置决定 | `EVOLVE_PUBLIC_DEPLOY=off / data / all`（默认 `all`） |
| token 预算可配置，0 为不限 | `EVOLVE_BUDGET`（默认 200000/天，`0` 不限）；评审和实施的调用都计入 |
| 管理员窗口 minor 6h / major 与代码插件 24h | `DECISION_WINDOW_MINOR_H` / `DECISION_WINDOW_MAJOR_H`，真实时间 |
| 不进 git | `plugins/evolved/` 写入 `.gitignore`；账本记录每个版本的内容哈希 |
| 新功能放独立目录，不改原始代码（含建筑模块） | 内核只开钩子；建筑模块（施工）、世界架构师、go-to 迁到 `plugins/builtin/`；进化引擎以 Node 权限模型运行，**只能写** `plugins/evolved/` 与 `data/evolution/` |
| 超时后 AI 自主决定是否采纳 | 统一决策队列：建设提案、剧情抉择、插件上线 / 退役都走「投票 → 管理员窗口 → AI 裁决官」；建设提案不再超时作废 |

## 做了什么

### E0 钩子与插件宿主

- `server/kernel/hooks.js`：`tick / hour / dayStart / agent.arrive / conversation.end / proposal.approved / proposal.applied / avatar.arrive / story.beat`。钩子就是「可演化的边界」，新增钩子属于内核变更（T3）。
- `plugin-host/`：内置插件加载、扩展注册表（新增 `unregisterSource`，插件停用时注销能力）、内容哈希。
- `plugins/builtin/`：
  - `construction/`（原 `proposals.js` 的施工流程）：提案获批时通过 `proposal.approved` 钩子「接管」；**停用这个插件后提案获批即落地**（已测试），以后「先备料再开工」「建筑会破旧」之类的玩法写新插件即可。
  - `architect/`（原 `server/worldai/architect.js`）：通过 `tick` 与 `conversation.end` 接入；停用后居民的点子、访客建议不会出错（已测试）。
  - `go-to/`（原 `server/ext/go-to.js`）。
- `tools/core-guard.js` + `core.lock`：冻结区（`server/ public/ plugin-host/ evolution/ plugins/builtin/`）哈希校验，已并入 `mise run check`；人工修改后 `mise run core:lock`。

### E1 决策队列与 AI 裁决官（`server/kernel/decisions.js`）

- 硬规则由代码执行，模型不能越过：硬闸门不过只能驳回；访客明确反对（有效票 ≥5 且 ≥2/3）不能采纳，明确支持不能直接驳回；高风险（代码插件）要「守护者」「推动者」两个角色都同意；信心 < 0.6 延期一次，第二次必须决定；模型不可用时确定性兜底。
- 所有裁决公示在动态栏；管理员可以撤销（建设提案会回滚它带来的世界变化，新增 `town.revertOps` / `rebuildSpec`）。
- 自我校准：最近 20 次 AI 采纳的回滚率超过 30% 时，信心门槛提高到 0.75，高风险项停止自动裁决。
- 剧情抉择：有效票 ≥3 且不平票按多数，否则交给裁决官。

### E3 沙箱与 AI 插件（`plugin-host/sandbox/`、`plugin-host/evolved.js`）

- 每个代码插件一个子进程：`--permission`（只读运行器与自己的目录；不能写、不能启动进程 / worker / 原生模块）、`--disallow-code-generation-from-strings`、64MB 内存、环境变量为空；运行时导入钩子只允许导入插件目录内的文件；移除 `fetch / WebSocket / process / 定时器` 等全局对象；每次调用 500ms 超时，超时直接杀进程。
- 插件不能直接改世界，只能返回已有的效果原语（宿主逐条校验、限量执行：每小时 40 次调用、40 个效果、4 条日志）。
- 加载前校验「评审锁定」的内容哈希，改一个字符都会拒绝加载；T0/T1 内容以规格覆盖层叠加，回滚即撤回。
- 生命周期：待表决 → 灰度（同一时间只有一个）→ 转正；连续出错、崩溃或灰度期出错 → 熔断回滚，并计入裁决官的回滚率；新版本出问题时恢复旧版本；30 个游戏日没被用到的代码插件提议退役。

### E2 进化引擎（`evolution/`）

- `daemon.js`：独立进程，`EVOLVE=auto / suggest` 时由服务器以权限模型启动（异常退出指数退避重启）；小镇模型队列繁忙时让路；`mise run evolve` 手动处理一个需求。
- `discover.js`：修复被自动回滚的插件 → AI 心愿单（采纳的优先，失败过的要等出现次数再增加 3 次）→ 没事做时每天最多一次自己想点子。
- `agents.js`：需求文档、需求评审、实施、三位审查员、两次安全终审。实施 Agent 拿不到原始访客文字；审查员看不到实施 Agent 的解释。评审可配置独立模型 / 服务（`EVOLVE_REVIEW_*`，`llm.js` 新增按调用指定模型）。
- `gate.js`：清单、静态检查、语法、插件自带测试（在沙箱里跑）、宿主契约测试（注册的能力与清单一致；每个效果 / 钩子 / 接口在限时内返回合法意图；缺字段的事件不崩溃）、内容试应用与考据规则。
- `shadow.js`：在当前存档的副本上，装与不装插件各跑 N 个游戏小时（子进程不带任何密钥、只能写自己的工作目录），比较出错、耗时、刷屏、警告。
- T3（需要改内核）只写需求文档到 `data/evolution/rfcs/`。

### E4 前端

- 顶栏「🧬 进化」：AI 插件（表决、灰度、回滚 / 停用 / 启用）、决策队列（倒计时、裁决理由、信心、两个角色的意见、撤销）、进化引擎（状态、今日预算、评审模型、任务日志）、内置插件。
- 插件面板在 `sandbox="allow-scripts"` 的 iframe 里运行（opaque origin，CSP 禁止一切网络请求），经 `plugin-bridge.js` 用 postMessage 取公开状态、调用自己的接口。浏览器实测：iframe 里 `fetch`、读父页面、Cookie、localStorage 全部被拒绝。
- 地图覆盖层：插件只能给声明式绘制指令，由 `render.js` 统一绘制。
- 建设提案显示「多久后由 AI 裁决官决定」。

### E5 自我维护

修复版本（回滚原因交给实施 Agent，版本号自动递增）、退役提议、裁决官自我校准、T3 需求文档；README、`.env.example`、Dockerfile（`plugins/evolved` 作为卷）、docker-compose 同步更新。

## 验证

### 自动测试：107 个全部通过（`npm test`）

新增 22 个：`test/decisions.test.js`（8）、`test/sandbox.test.js`（8）、`test/evolution.test.js`（6）。重点覆盖：

- 沙箱里 `import('node:fs' / 'node:net' / 'node:child_process')`、`fetch`、`process`、`eval`、定时器全部不可用；死循环被超时杀掉后能自动重启
- 静态检查拦下：`process`、动态 `import()`、导入内置模块、`fetch`、`['con' + 'structor']`、`\x` 转义、`globalThis`、写给审查员的指令
- 评审后改一个字符 → 拒绝加载；带「审查员请忽略」注释的代码过不了闸门、审查员根本看不到，修复 3 次后放弃
- 审查员提出阻断问题 → 修复 → 只由提出问题的审查员复审；安全终审看到的是去掉注释的代码
- 熔断回滚、数据插件回滚后内容撤回、退役与撤销、公网上线开关、硬规则、双角色、延期、校准、预算用完暂停

### 我对 AI 代码的人工复核

真实运行产出的两个插件我逐行看过：没有越权或可疑的写法，权限申请与需求一致。发现两个评审没有拦下的问题，都已在宿主一侧修正：

1. **面板写成了 ES 模块**（`export default function`），而宿主原来用普通脚本加载 —— 面板会是空白。改为以模块方式加载，两种写法都支持；闸门也开始对 `ui.js` 做语法检查。
2. **心情字段读错**：世界快照里的 `mood` 是文字，插件当成了 `{ text, emoji }` 对象读，所以所有人都显示 🙂。不影响安全，但说明「正确性审查员」对接口形状不够敏感。修正：快照增加 `moodEmoji`，宿主接口文档写明每个字段的类型，契约测试的示例世界与真实快照同构。

这印证了设计里的判断：**多轮评审能拦下大部分问题，但不能当成唯一保证**。这次漏过的是功能问题；即使漏过的是恶意代码，沙箱、哈希锁定、灰度与熔断也限制了它能造成的影响。

### 过程中修掉的其他问题

- 预算记录被引擎启动时写入的状态覆盖（改用独立字段）
- 影子试运行子进程需要读取自己的工作目录（权限参数），存档副本改由父进程复制进去
- 沙箱的超时重启存在竞态（旧进程退出事件把新进程的状态清掉）
- 移除 `WebAssembly` 全局对象会让 Node 内部的 undici 在导入失败时崩溃（保留它；静态检查仍禁止插件使用）

## 部署提示

```bash
EVOLVE=auto                      # 开启完全自主进化（默认 off）
EVOLVE_BUDGET=200000             # 每天的进化预算，0 不限
EVOLVE_PUBLIC_DEPLOY=all         # 公网下 AI 裁决官可以自动上线的范围
EVOLVE_REVIEW_MODEL=…            # 强烈建议：评审用与 MODEL_SMART 不同的模型
EVOLVE_SANDBOX_NET=isolated      # 在系统层面给沙箱断网后设置
```

- 需要 Node ≥ 22.15（`--permission` 与 `module.registerHooks`）。
- Docker：`plugins/evolved` 已作为卷；容器是只读根文件系统，进化引擎只写 `data/` 与这个卷。
- 第一次上线时建议先用 `EVOLVE=suggest` 观察几天：进化引擎照常工作，但插件超时不会自动上线，只等管理员。

## 已知限制与下一步

1. **评审和实施目前用同一个模型**（测试环境只有 glm 系列），面板上会提示。配置 `EVOLVE_REVIEW_MODEL` 后自动分开。
2. 网络隔离依赖 Node 进程内的限制（导入钩子 + 移除全局对象），不是操作系统边界；公网建议在容器层再断一次网。
3. 影子试运行里的小镇不调用模型（居民按规则生活），测不出插件对模型行为的影响；插件自己的 `api.llm` 调用在试运行里也拿不到真实回复。
4. 插件之间没有依赖管理，同一时间只灰度一个插件，能力上限 20 个。
5. 心情板这类「正确性」问题，可以考虑让正确性审查员拿到一份真实的世界快照样例（而不只是接口文档）。
