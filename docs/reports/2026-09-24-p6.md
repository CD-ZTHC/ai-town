# P6 扩展：完成汇报

> 日期：2026-09-24　分支：`claude/lucid-lamport-ye9rtq`（[CD-ZTHC/ai-town#1](https://github.com/CD-ZTHC/ai-town/pull/1)）
> 对应设计：[`docs/design/ai-world-evolution.md`](../design/ai-world-evolution.md) 第 12 节 P6；另外补上了真实模型测试后提出的两项改进：随 AI 负载调速、每游戏日用量统计。

## 一、结论

P6 四项都已完成，外加两项来自实测结论的改进：

| 内容 | 结果 |
| --- | --- |
| 异界口袋地图「暗月界」 | 共存结局会打开它，管理员也能手动开关。居民经月之渡口往返两张地图，画面可以切换，也会跟着居民切过去。 |
| 时间线分支 | 可以从此刻或任意整点快照分叉，各分支独立存档、可以来回切换，互不影响。 |
| 访客化身 | 访客起个名字就能在镇上现身走动。居民看得见、会打招呼，聊天时知道是谁、是否站在面前，记忆里也记下名字。 |
| Mod 导出 / 加载 | 可以把 AI 创造的内容导出成 Mod，别的小镇加载后从第一天起就拥有。自带一个真实模型实测时产生的 Mod。 |
| 随 AI 负载调速 | 模型排队过长时自动放慢时间（最低 1/4），顶栏会提示。 |
| 每游戏日用量 | 按游戏日记录 token 用量和调用次数（分模块），重启后保留。AI 大脑面板显示最近几个游戏日的平均用量。 |

## 二、做了什么

### 1. 暗月界（多区域）

- **地图**（`server/world.js`）：`buildMoonRealm()` 生成 36×26 的浮岛，有四个地点：月之渡口·彼岸、暗月广场、月光花园、星坠崖。另外有月光井、紫晶、月光花、紫色路灯。新增三种瓦片：月面、虚空、月径。
- **规格**（`server/kernel/spec.js`）：
  - `regions` 新增 `moonrealm`。
  - 异界地点带 `region` 字段，校验器会检查区域是否存在。
  - 能力清单把异界地点单独列出，并注明「不能建房」，架构师的选址也只在小镇里进行。
- **模拟**（`server/sim.js`）：
  - 居民多了 `region` 字段。
  - 目的地在另一个区域时，居民先走到本区域的渡口，穿过去再继续走。穿越两端都有涟漪特效；第一次过去的人会留下记忆和动态。
  - 地点解析、公共地点列表、「身边的人」、对话触发都按区域区分。关闭的区域不会出现在居民可选的地点里，LLM 写了也会回落到家。
  - `effects.js` 的 `posOf` / `agentsNear` 和 `rules.js` 的 `nearStructure` 也按区域判断，特效会带上区域。
- **剧情**：
  - 新增特权节拍 `{kind:'region', id, open}`，只有剧情弧能用，导演不能用。
  - 《镜湖裂隙》的「双月当空」结局会打开暗月界，那边出现三只友善的小影灵：月月、萤萤、朦朦。
  - 关闭通路时，还在那边的居民会被送回小镇渡口。
- **生物**（`story/creatures.js`）：生物带 `region` 字段，新增 `addFriend()`。结局收尾只遣返小镇里的生物，遭遇和怕光判断只在同一区域内进行。
- **前端**：
  - 新增月面、虚空瓦片的绘制，浮岛边缘有微光，月光井、紫晶、月光花也有专门的绘制。
  - 暗月界永远是紫色黄昏，灯光为冷紫色，没有小镇的天气。
  - 顶栏「🌗」按钮切换区域；画面只显示当前区域的居民、生物、构筑物和特效。
- **接口**：管理员 `POST /api/region`；SSE 新增 `regions` 事件。

### 2. 时间线分支（`server/timelines.js`）

- 主时间线仍是 `data/`，分支放在 `data/timelines/tl-N/`，登记表是 `data/timelines.json`。最多 12 条。
- 分叉：来源可以是当前存档（先存盘），也可以是某个整点快照。快照名、时间线 id 都用白名单正则校验，路径不会越界。
- 切换：先存盘，再停止当前小镇，然后在目标目录新建小镇，并向所有客户端广播 `init`。重置、回溯都作用于当前时间线。
- 界面：「🛠 建设 → ⏳ 时间线」列出所有时间线（写明从哪条、第几天几点分出）。可以从此刻分叉，每个快照也都有「🌿 分出」和「回到这里」两个按钮。

### 3. 访客化身（`server/avatars.js`）

- 现身：`POST /api/avatar {name, color}`。
  - 名字最多 8 个字，经内容审核，不能和居民或其他访客重名。
  - 每个 IP 同时只有一个化身，全镇最多 `AVATAR_MAX`（默认 8）个；每个 IP 每小时最多现身 6 次。
- 走动：`POST /api/avatar/move {location}`。只能去开放的公共地点（包括异界，同样经渡口），3 秒冷却。
- 离开：`POST /api/avatar/leave`；20 分钟不操作也会自动离开。化身只在内存里，不进存档，不消耗模型额度。
- 居民感知：
  - 「身边的人」里会出现「附近还有外地来的访客：旅人「小满」」。
  - 化身走到认识的居民身边时，对方会说「又见面了，小满！」；陌生的居民有 30% 的概率打招呼。这些都不调用模型。
  - 和居民聊天时，提示词写明是「站在面前的」还是「远处的」旅人「小满」，记忆里一定带上名字。

### 4. Mod（`server/kernel/mods.js`、`tools/export-mod.js`）

- 只导出内容类操作：建筑、节日、天气、物品、构筑物、能力、法则、设定。加上 `--proposals-only` 时，只导出经建设提案落地的内容。
- 加载顺序：默认规格 → Mod → 存档操作历史，每个操作都走运行时的同一套校验。冲突的操作会被跳过并写进日志；Mod 内容不写进本小镇的历史。
- 自带 `spec/mods/lakeside-story-corner.json`：上次真实模型实测中，林晓雨聊出来的点子，由世界架构师设计落地（码头边的「湖畔故事角」+「湖边老故事会」）。
- 说明文档：[spec/mods/README.md](../../spec/mods/README.md)。

### 5. 随 AI 负载调速 / 每游戏日用量

- `PACE_WITH_LLM`（默认开）、`PACE_QUEUE`（默认 6）：排队数超过阈值时，时间流速按 `阈值/排队数` 放慢，最低 1/4。深夜快进和没有配置模型时不受影响。
- `llm.stats.byLabel` 按模块统计调用次数、失败次数、token 和耗时。
- 每天开始规划时记下前一个游戏日的用量，保留 30 天，写入存档。跨越重启、计数出现负数的那一天不记录。
- `GET /api/usage` 返回每日明细和平均值。

## 三、验证情况

- **测试：共 85 个，全部通过**。本阶段新增 9 个（`test/p6.test.js`），另外更新了 2 个：
  - 调速：排队 12 → 半速，排队 100 → 1/4，排队少或关闭调速 → 正常速度
  - 每日用量：记录、平均值、存档保留
  - Mod：导出过滤、只导出提案内容、非法 id 被拒、加载时坏数据和路径穿越被跳过、不写进本地历史；仓库自带的 Mod 能加载
  - 时间线：分叉、切换、分支变化不影响主时间线；非法快照名、目录穿越、不存在的时间线都被拒绝
  - 暗月界地图：所有站位都可以走到
  - 区域完整流程：
    - 关闭时去不了
    - 打开后中文地名也能匹配
    - 林晓雨经渡口走到月光花园、记下第一次穿越，再走回家
    - 不同区域的人不算「在身边」
    - 关闭通路时被送回小镇
  - 区域节拍：导演不能用、剧情弧可以用；开放状态随存档保留
  - 访客化身：
    - 名字审核、重名检查、同一 IP 只保留一个化身
    - 关闭的区域去不了，移动有冷却
    - 能走到码头、被身边的居民看见
    - 聊天提示词带名字，记忆里有名字
    - 超时离开
  - 更新的测试：共存结局的断言（小镇里留一只小影，暗月界有三只）
- **浏览器**（Playwright，本地服务器）：
  - 现身、打开区域、切换到暗月界、化身移动、时间线面板、分叉并切换、再切回主线，整个流程都正常，页面没有脚本错误。唯一的控制台报错是这个环境访问 Google 字体时的证书问题，与本次改动无关。
  - 截图显示暗月界的紫色浮岛、月光井和小影灵都渲染正常。
- **真实模型**（glm-5.3-flash / glm-5.3，测试密钥）：各跑一个完整游戏日。

| 倍速 | 真实耗时 | 调用 | 失败 | token | 调速生效 |
| --- | --- | --- | --- | --- | --- |
| 20× | 76 秒 | 31 | 0 | 35,369 | 2 秒 |
| **3×** | **6 分钟** | **65** | **0** | **88,396** | 19 秒，最低 0.6 倍 |

3 倍速一天的用量构成：

| 模块 | 调用 | token |
| --- | --- | --- |
| 对话 | 11 | 25k |
| 内心独白 | 21 | 21k |
| 规划一天 | 8 | 12k |
| 写日记 | 8 | 9k |
| 反思 | 7 | 8k |
| 叙事导演 | 3 | 6k |
| 日报 | 1 | 3.5k |
| 架构师 + 考据 | 2 | 3k |
| 群体心智 | 4 | 1k |

从这两次测试可以得出：

- **每游戏日约 9 万 token**，和之前估计的 6~10 万一致。按这个用量，每日 15 万的预算大约够 1.5 个游戏日。
- 20 倍速下用量少，并不是更省：模型跟不上，很多思考和对话根本没来得及发生。**正式运行建议 1~3 倍速**。
- 第一次跑时没有设置 `MODEL`，网关拒绝了默认模型名，55 次调用全部失败，小镇靠规则兜底照常运行。补上模型名后重跑正常。部署时 `.env` 里一定要写明 `MODEL` / `MODEL_FAST` / `MODEL_SMART`。

## 四、已知限制

- **只有一个异界区域**，而且是手工设计的生成器。AI 目前不能创建新区域，也不能在异界建房（能力清单里已经说明）。以后可以把「新增区域」做成一种大改级的世界补丁。
- **异界里没有天气和昼夜变化**（永远是黄昏），生物的偷窃、追逐行为也只在小镇里出现。
- **访客化身不进存档**：服务器重启或切换时间线后需要重新现身。化身之间不能互相看见名字以外的信息，也不能和其他访客聊天。
- **时间线分支不会自动清理**：每条大约是一份存档的大小，超过 12 条需要手动删除 `data/timelines/tl-N/` 并编辑登记表。`mise run reset` 会一并清掉所有分支。
- **Mod 卸载**：去掉 `MODS` 后，居民记忆和日程里提到 Mod 地点的内容仍然留着，只是地点会被当作无效，回落到家。
- **调速只看排队数**：正在执行的请求不算在内。模型很慢但并发足够时，不会触发放慢。

## 六、建议

1. **在生产环境以 1~3 倍速完整跑一季（7 个游戏日）**，把每日预算设在 10 万左右。重点观察三件事：《镜湖裂隙》能否在真实模型下自然走到结局并打开暗月界、居民会不会自发去异界、心愿单里会冒出哪些缺口。
2. 如果想省 token，**对话和内心独白是大头**（合计约一半）。可以考虑两个办法：降低白天的对话概率（参数 `convoBaseProb`）；或者只在剧情张力高时增加内心独白。这两个都可以通过世界操作调节，不用改代码。
3. 心愿单里出现「新增区域」「在异界建房」一类的缺口时，就按 P5 的流程生成 RFC，再把区域纳入世界补丁。
