# P5 自我进化闭环：完成汇报

> 日期：2026-09-24　分支：`claude/lucid-lamport-ye9rtq`（[CD-ZTHC/ai-town#1](https://github.com/CD-ZTHC/ai-town/pull/1)）
> 对应设计：[`docs/design/ai-world-evolution.md`](../design/ai-world-evolution.md) 第 7 节；已确认的决定：**只生成需求文档，不自动开 PR**

## 一、结论

P5 已完成，验收标准达到了：**一个真实的能力缺口生成了需求文档，按文档实现并合并后，被运行中的 AI 使用**。

这次实际走通的闭环：

1. **发现缺口**：叙事导演想「萤火节傍晚，把镇上的人都召集到码头一起放灯」。世界架构师发现能力清单里没有「让居民立刻动身前往指定地点」，于是把它记入 AI 心愿单。
2. **采纳**：管理员在心愿单里点「采纳」。
3. **生成文档**：`mise run evolve` 生成需求文档骨架（这个环境没有模型密钥，所以用的是离线模式）。
4. **补全文档**：维护者（这次由我扮演）补全设计，得到 [RFC 0001](../rfcs/0001-go-to.md)。
5. **实现**：在扩展点实现 `server/ext/go-to.js`，新增效果原语 `goTo`，**没有改动任何内核代码**。
6. **自动可见**：能力清单自动包含 `goTo`，世界架构师的提示词里也能看到它。
7. **被 AI 使用**（测试里用模拟模型验证）：架构师用 `goTo` 设计出新能力「召集铃」→ 提案落地 → 何月摇铃 → 身边的人一起走到了码头。

## 二、做了什么

| 模块 | 作用 |
| --- | --- |
| 能力清单 `worldai/manifest.js` | 从代码自动生成「AI 现在能做什么」：世界操作、效果原语、表达式函数、特效、体型、参数范围、现有地点 / 物品 / 能力。**架构师提示词里原来手写的清单改为由它生成**；`mise run manifest` 输出 `docs/capabilities.md`；有测试保证文档与代码同步。 |
| 扩展点 `server/ext/` | 注册表 `registerEffect(name, {doc, check, apply})`、`registerExprFn(name, impl, doc)`；加载器在启动时自动导入。约束：只能新增、不能覆盖内核能力；名字必须合法；必须带说明（会进入能力清单）；加载失败直接中止启动，避免带着半套能力运行。内核导出 `checkTarget` / `resolveTargets` 供扩展复用。 |
| AI 心愿单 | 缺口来源新增一处：导演想用但系统里没有的剧情动作。缺口有「待处理 / 已采纳 / 已忽略」三种状态，管理员在面板里处理；已经生成需求文档的缺口会显示文件路径。 |
| `mise run evolve`（`tools/evolve.js`） | 读取存档里已采纳、还没有文档的缺口（`--all` 时也包括待处理的），生成 `docs/rfcs/NNNN-*.md`。有模型时由强模型按固定结构撰写（摘要、动机、设计、参数格式、使用示例、测试要点、风险、备选方案、工作量），缺口描述只作为数据；没有模型或加 `--offline` 时，生成带数据的骨架。支持 `--dry-run`、`--limit`；编号自动递增；对应关系记在 `data/evolve.json`，不会重复生成。 |
| 需求文档目录 `docs/rfcs/` | README（流程、命令、扩展写法）、`0000-template.md`（由生成器输出，格式一致）、`0001-go-to.md`（已实现）。 |

## 三、验证情况

- **测试：共 74 个，全部通过**（约 2 秒）。本阶段新增 9 个，覆盖：
  - 扩展注册的各种拒绝情况
  - 扩展表达式函数在规则里可用
  - `goTo` 的校验，以及睡着 / 交谈中的人不受影响
  - 能力清单和架构师提示词包含扩展
  - 「召集铃」完整闭环
  - 导演的未知动作记为缺口、心愿单状态、只有管理员能看到心愿单
  - `evolve` 离线模式：只处理已采纳的、`--all`、编号、不重复生成、演练模式、被忽略的不生成
  - `evolve` 模拟模型撰写
  - 能力清单文档与代码同步
- **实际运行**：
  - `mise run evolve --offline` 生成了 0001 的骨架。
  - `mise run manifest` 生成了 `docs/capabilities.md`，其中 `goTo` 标注为「扩展」。
  - 浏览器里心愿单页的采纳 / 忽略 / 重新打开、「已有需求文档」显示都正常，页面没有脚本错误。

## 四、已知限制

- **缺口合并比较粗糙**：用的是双字组相似度，阈值 0.5。意思相近但用词不同的缺口（如「拆除或搬迁已有建筑」和「拆掉已有的建筑」）不会合并。调低阈值又容易误合并。以后可以在 `evolve` 阶段让模型做一次语义归并。
- **扩展点只覆盖服务端**：效果原语和表达式函数。需要新画面的能力（新特效、新生物体型）仍然要改前端代码，前端扩展注册表留待真正需要时再加。
- **`evolve` 生成的只是文档**：它不评估可行性和优先级，由维护者判断。缺口多时建议先在面板里筛选，再生成。
- **模型撰写的文档质量还没验证**：和前几个阶段一样，没有接真实的 glm 模型。

## 六、建议

在继续加功能之前，最值得做的是**接上真实的 glm-5.3 / glm-5.3-flash，在本地用 20 倍速跑完整的一季**，观察这几项：

- 导演、多人场景、架构师、考据官的输出质量
- 每日 token 用量
- 心愿单里实际会冒出哪些缺口

这些真实数据会决定 P6 以及后续 RFC 的优先级。
